A parity run of one rule in three runtimes holds the RULE, not each side's code round it: give the rule every input the call sites compute (a frame's turn, the play's scale) as its own argument so the parity cases can vary them - a flipped piece's outline was mirrored in the wrong space only where the frame was turned, which no case did. And work out a step's pushes from one snapshot and add them: applied one after another, pushes that should cancel leave a piece creeping for ever.
