# parallax-systems

Plan + ideas: `board/plans/archive/2026-10-12-systems-pipeline-v2.md`. Green specs are not a working game: prove it.

## Every game is a folder (FIRST, always)
The owner says "we are making <game>"? `lune run kit game new <Pascal>` before anything else (`kit game use <Name>`
to continue one; `--game <Name>` on a single command). It makes `games/<Name>/` — `GAME.md` (the brief: ASK THE OWNER
its questions first; `kit game check` lists the open ones), `src/{server,client,shared}`, `assets/`, `tests/`, its own
`board/` (tasks + handoffs), `docs/`, a Rojo project and a synced copy of the kit runtime — and makes it ACTIVE: every
kit command then reads and writes inside it (`kit status` says which game). The layout is in `games/<Name>/README.md`.
Gameplay code never lands at the project root: `kit new system` refuses without a game, and `kit verify` fails on new
root files (`games/legacy-root.json` = the scratch that was there before). Prove a game: `kit game check`,
`kit verify --game <Name>`; serve it: `rojo serve games/<Name>/default.project.json`.

## A new game
`kit new game <Pascal>` (= `kit game new`) → the folder above, then `<Name>Server` / `<Name>Client` entry points; every service is a ModuleScript in
`<Name>Services` (`return { deps = { "DataService" }, init = fn(self, services), start = fn(self, services) }`), run
by `kit.Loader` in dependency order (cycles and unknown deps named); `DataService` (ProfileStore session-locked saves
once `kit add profilestore`; memory + one warning before); tunables in `src/shared/<Name>Config` read LIVE through
`Configs.bind("<Name>", <Name>Config)` (Experience Configs: change values without a republish; a wrong-typed / NaN /
negative live value falls back to the code's).

## A new system
1. `kit new system <Pascal>` → Config + Rules (pure) + Service + Controller + spec.
2. Every DECISION in `<Name>Rules` + a spec case (hostile input too) → `kit fuzz <Name>Rules` (a throw = a crash;
   saying yes to NaN / inf / a wrong type = a warning) → `kit mutate <Name>Rules` (planted bugs your specs miss).
3. **Remotes from a schema**: `assets/net/<System>.net.json` → `kit net` → `src/net/<System>Net.luau`
   (`ReplicatedStorage.Net`). Server: `Net.Request.on(function(player, target: Vector3, power: number) ... end)` — the
   generated wrapper rate-limits per player and Guard-checks EVERY argument before your handler runs; client:
   `Net.Request.fire(...)`. The schema refuses an unbounded client number, an unlimited string, a vector3 with no
   magnitude cap, a request with no rate. `kit verify` fails if a generated file is edited or stale.
4. The EFFECT in the Service; the Controller only gathers input and shows feedback.
5. `kit verify` (the security audit runs inside it); a playtest (`kit new playtest`) — it FAILS on any script error in
   the console, named with its line.

## Combat: moves as data
`assets/moves/<Move>.json`: `anim`, `frames` (or `"from_anim"`: startup / active / recovery from the anim lane's
MEASURED phases, active widened to 3 frames), `hitboxes` per frame (size, offset), damage, stun, knockback [right, up,
forward], hitstop, blockstun, `block` (blockable / chip / unblockable), parryable, `cancel` { into, from, to },
`sfx` / `vfx` cues by frame, `onHit`. A set: `assets/moves/sets/<Set>.json` (`moves`, `combo`, `health`).
`kit move` validates (ghost hitboxes outside active frames, huge boxes, combo links that are not cancels), measures
on-block advantage + combo damage + time-to-kill, writes `src/moves/<Set>.json` (`ReplicatedStorage.KitMoves`) and a
MOVE SHEET `build/moves/<Set>.png` — look at it. In game: `Moves.serve("<Set>")` (server: cancels, combo scaling,
per-frame `GetPartBoundsInBox` hitboxes on the server's own positions, hit / block / chip / parry / i-frame dodge,
damage, stun, knockback, hit-stop, Sfx / Vfx from the data; NPCs: `.use(character, move)`; `Moves.debug(true)`) and
`Moves.client("<Set>").use / block / parry`.

## Server request order (the audit enforces it)
enabled → `limit:take(player.UserId, os.clock())` → `Guard.*` on EVERY client argument → `Rules.check(...)` → act →
reply. A malformed packet returns silently. Never trust client positions, damage, prices or ownership.

## Kit runtime (ReplicatedStorage.kit, kit-owned — don't edit)
Guard · RateLimit · Loader · Configs · Moves / MovesRules · Sfx / SfxRules · Vfx · Anim · Ui · Assets · Environment.
`src/shared` is pure (no `game:GetService`, no `Instance.new`); siblings via `require("./X")`. Strict mode, stylua +
selene clean, `task.wait/delay/spawn`. Per-player tables cleared on `PlayerRemoving`.

## Proven libraries (`lune run kit add`)
profilestore (ALL saves) · trove (cleanup) · cmdr (admin console, gated) · zap (typed networking for big games).
Anything else: vet it first (kit-vet skill, VETLOG.md). Examples: `lune run kit examples system`.
