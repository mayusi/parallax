# parallax-qa

## 1. Static (no Studio)
- `lune run kit audit` — every `OnServerEvent`/`OnServerInvoke` handler: each client argument must be validated
  (Guard / typeof / type / a check function) and the handler rate-limited. Also flags `require(<asset id>)`
  (free-model backdoor), `loadstring`, server `InvokeClient`, `getfenv/setfenv`, `FireAllClients` in loops.
  It runs inside `kit verify`. Accepted risk? Add `"file:line"` to `qa.auditIgnore` in kit.config.json + a note why.
- `lune run kit verify` — the full gate. `lune run kit selftest` — proves every gate still catches bad input.

## 2. In-engine playtests (Studio open + Rojo connected + Studio MCP)
1. `lune run kit new playtest <name>` → `tests/playtest/<name>.luau`. First line picks the side:
   `-- runs on: Server` (assert game state, call server code) or `-- runs on: Client` (fire remotes like a real
   player, read the UI). Built-in: `smoke` (player spawns alive, kit runtime present, no instance growth).
2. Write checks with the test API:
   `t.check(name, cond, detail?, fix?)` · `t.wait(s)` · `t.waitFor(fn, timeout?)` · `t.player(timeout?)` · `t.find("A.B.C")`.
   Give every check a `fix` hint — it becomes the next_action when it fails.
3. `lune run kit playtest bundle <name>` and follow the printed steps exactly:
   `start_stop_play(true)` → `execute_luau` (datamodel from step 1, code = the bundle file) → save the returned
   JSON to `build/playtest/<name>.result.json` → `start_stop_play(false)` → `lune run kit playtest record <name> <file>`.
4. While it runs, skim `get_console_output` for errors. Every bundle also measures memory, workspace instances
   and frame time against `qa.perf` in kit.config.json (Studio's memory figure includes the editor).

## 3. Exploratory (when the human asks "test it")
Play the feature like a hostile player: spam the action, send it from far away, act while dead / mid-respawn,
two players at once, leave mid-action. Turn every bug found into a playtest check or a spec case, then fix.
Report: what you tried, what broke, what is now covered — on the task (`kit task note`) and in the handoff.

## Rules
- Screenshots (`screen_capture`) only when a check can't express it (pure visuals) — max one per iteration.
- Never "fix" a failing playtest by loosening its check; fix the game or record the accepted risk.
