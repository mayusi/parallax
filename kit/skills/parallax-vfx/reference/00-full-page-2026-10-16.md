# parallax-vfx

## The originality rule (owner, 2026-10-13 — a MUST)
Every effect gets its OWN look from its own SOURCE's real frames (the anime / game it comes from), at anime quality —
never Starblade's (or any earlier piece's) frames, title card, glow vocabulary or camera grammar, and never a genre swap
to look "different" (Delaware v2 printed like a comic book was rejected as trash). Study the source's actual impact
frames and effects in the refs and build THOSE. For a big reinterpretation, show one test frame and ask first.
Optional tools exist (impact style `comic`, `post.outline`, mesh `toon`/`outline`, `booth.sky: day`) — use them only
when the source really looks that way.

## The library rule (owner, 2026-10-12 — a MUST, enforced by `kit verify`)
EVERYTHING the VFX pipeline makes is saved in `library/vfx/`, packaged by part and named properly: every effect
(source, the expanded version that plays, previews, recordings at 640 px, the owner's verdicts, every earlier
version), every part, every texture (spec + finished sheet), every mesh — each with a README (what it is, who uses it,
how to reuse it). `kit vfx` and `kit vfx play --record` save it; `kit verify` fails on anything missing or stale.
- **Reuse before making**: `kit vfx vault find "<words>"` → read `library/vfx/<kind>/<name>/README.md` →
  `kit vfx vault get <effect> --as <new>` (the effect + its parts + textures + uploaded ids), or `"use"` a part.
- **The owner's words are data**: `kit vfx vault verdict <effect> "<words>" [--score N]` the moment they judge — the
  verdict stays tied to that exact version, and that version is never lost.
- Saving by hand (after editing outside `kit vfx`): `lune run kit vfx vault`. Never delete from `library/vfx/`.

## The loop (one pass, look every round)
0. `lune run kit lessons vfx` · `lune run kit examples vfx` (proven presets: `starblade` is the v3 reference).
1. **Beat sheet first.** Name the move and its role (basic hit / skill / ultimate). Pick 2-3 reference shots of the
   real thing (anime, games). Write the beats with times (wind-up -> release -> body -> residue), a palette of ~5
   colours, the dominant shape (column / cone / ring / dome), and the size the PLAYER sees: a 40-stud throw is watched
   from ~50 studs, where a 16:9 screen is ~125 studs wide.
2. **Textures from Blender** — `assets/textures/<key>.json` with `"engine": "fx"` and a recipe (below). Reuse the
   library first (`assets/effects/_textures.json`). `lune run kit vfx` renders only what changed (Cycles on the GPU),
   finishes it (glow, white-hot core, alpha, sheet) and registers it. LOOK at `build/textures/_fx_review.png`
   (every texture over black and grey). Then `lune run kit upload --only build/textures/<key>.png` (live in Studio
   within seconds; textures that are not uploaded play as stand-ins).
3. **Preset** — `assets/effects/<name>.json`, `"version": 3`, layers (below). `lune run kit vfx` validates it (the same
   validator the game runs): cut-off layers, unknown textures / points, flipbook vs sheet, particle budget.
4. **Real engine** — `lune run kit vfx booth <name> [--views player,side,hero] [--moments 0.2,1.5,2.6]` writes the run's
   Studio script and prints the steps (the shared capture bridge, `kit/tools/studio_capture.py`, card 4s96: no network):
   start `python kit/vfx/capture.py studio ...` (background, FIRST), run `build/vfx/booth/<run>.studio.luau` through
   Studio (MCP `execute_luau`, Edit, the scratch place KitPlaytestScratch; answer "install" = run its `.install.luau`
   once), then after its seconds run `<run>.collect.luau` and save that JSON line as `<run>.result.json`. The script
   signals each frozen frame with a colour over the 3D view; the capture reads the place's window. The kit modules and
   the clip are the PLACE's (a place older than the repo is named in the summary: `lune run kit playtest place`).
   The booth builds a dusk arena with Roblox's own R15 character holding a sword (`@blade`, `@tip`, `@hilt`,
   `@bladeMid` anchors; its raise and chop follow `booth.motion` {raise, swingAt, swingTime}), plays the effect WITH
   its sounds, FREEZES it at every moment and holds it for the capture (which brings Studio to the front first, so
   particles keep up with the clock). Views: `player`, `side`, `hero`, `cine` (a camera PATH: close-up, push-in,
   beside the release, a sweep down the beam, wide on the impact — define your own in `booth.viewDefs` as
   `{ "path": [{ "t", "pos", "look", "fov" }, ...] }`). LOOK at `build/vfx/booth/<name>_all.png`.
   Watch it LIVE afterwards (the booth keeps the effect in the place) from Studio's command bar, Studio in front for
   full frame rate: `require(game.ServerStorage.KitStudioBridge.VfxBooth).replay("hero")` (player | side | hero).
   Videos: dense `--moments` (every 1/24 s) give mp4s; Studio renders ~5 fps when NOT focused, so particles lag the
   clock in those — keep Studio in front while recording.
4b. **Daily loop OUTSIDE Studio** — `lune run kit vfx play <name>` serves the browser player (kit/vfx/player, three.js
   vendored): the preset at full frame rate with the measured Roblox rules, a scrub bar, speed, views (the same
   kit/vfx/views.json cameras as the booth), per-layer mutes and a live brightness graph. `--record --views cine,player`
   renders every frame at 24 fps to `build/vfx/booth/<name>_play_<view>.mp4` + a contact sheet + `<name>_play.metrics.json`
   whose gate says: one intensity peak per declared hit (`preset.hits`), readable at range (>= 3% of the frame),
   <= 4 hues, not blown out. It is a PREVIEW: `python kit/vfx/calibrate.py <name>` compares its brightness curve
   with a booth recording of the same view and says which phase is off; the booth (Studio) stays the truth.
5. Fix what you SEE, re-run 3-4. Judge against the reference shots, never against a gate. Done: `kit promote vfx
   <name>`; learned something: `kit lesson vfx "..."`.

## How pro Roblox effects are built (measured studies of published effects; apply them)
- **Many layers, one sprite each**: a single slash hit is 40-60 layers; median emit count 1. Stack sprites timed in
  place, 25-50 ms apart. Nothing fires at the same time.
- **Brightness + bloom**: hot layers run `brightness` 5-50 (median 9); a white-hot core 50-150 for 0.03-0.1 s. Glows
  and halos: `lightEmission` 1 at brightness 1-6. Hard cel shapes: `lightEmission` 0 or negative.
- **Value**: bright reads only against dark — `twin` (a black / dim copy, same texture, zOffset -0.25..-1), dark
  tails in colour gradients, dark smoke against fire. White is a thin shape (rings, flares), not a fill.
- **Orientation**: `FacingCamera` puffs/glows, `VelocityPerpendicular` flat rings/crescents (needs speed > 0, even
  0.001), `VelocityParallel` + `squash` 2-3 streaks (sparks, speed lines, rising light).
- **Timing**: intensity only goes down after the hit, but an explosion's MASS keeps growing 0.25-1.3 s. Lifetimes:
  flash 0.03-0.15 · crescents 0.15-0.4 · body 0.35-1.2 · rings/debris 0.4-1.4 · smoke/marks 1-3 (scorch to 6).
  Anticipation 0.1-0.6 s (ultimates up to 2.5): energy gathers INWARD (`shape.inOut: "Inward"`).
- **Palette**: ~5 colours, saturated energy + desaturated matter (dust, rock) — always pair the two.

## Learned from references and shipped games (2026-10-11; sources in VETLOG.md and the memory note)
- **References first, in the folder**: `assets/effects/refs/<name>/` (ignored by git — copyrighted stills are private
  measure-only) holds frames of the target look; the player's `refs` panel shows them beside the viewport (`O`
  overlays one at 50%) and `kit vfx judge` puts them in the packet. Starblade: ufotable frames = hard-edged cel
  light (jagged lemon-yellow blades with white cores and a thin gold rim), a dense gold sparkle field during the
  gather, full white-out frames at release and impact, the beam as a THIN white line in a wide soft gold sheath.
- **Impact frames** (read from the owner's reference set: One Piece, MHA, Samurai Champloo, a Roblox game, a
  negative game frame — the full read is `board/plans/archive/impact-frames.md`; stills in `assets/effects/refs/impact_frames/`):
  TWO TONES and nothing else — a flat PAPER (white, black, or one flat hue) and an INK (the paper's opposite); the
  SUBJECT is the real pose of that frame flattened to a silhouette (never a redrawn illustration); the effect's
  ENERGY is thresholded to one thing (the paper, the ink, or ONE accent hue: gold, orange, red, cyan); RADIAL
  LINES converge on the hit (hundreds of thin speed lines, thick bristle wedges, a few huge dry-brush strokes,
  splatter); no sky, no lit ground, no bloom; the frames ALTERNATE light / dark / tinted, 2-4 frames each, clock
  held, then the white-out. Owner rulings 2026-10-11: a grade of the 3D scene is not one; a generated painting
  (a knight, a crater, a redrawn beam) is not one; "the impact frame should correspond to the vfx itself", "keep
  it black and white, maybe some yellow — it depends on the case of the visuals". Kit: `impact` with
  `"style": "frame"` BUILDS the frame from the scene at that instant: `paper`, `ink`, `accent` (what the hottest
  energy becomes; `hot` / `mark` override), `energy: [markT, hotT]` (0.22 / 0.8), `lines` (`speed_lines` |
  `bristle_burst` | `dry_brush` | `none`; `linesColor`, `linesScale` in screen heights, `linesStrength`), `focus`
  (a point; the hit), `subject` (`actor` = the rig + flying debris | `all`). Sequence per hit, inside the hitstop:
  white frame (speed lines, the effect's colour as the hot) 0.08 → black frame (white silhouettes, bristle burst)
  0.08 → white frame with dry brush 0.06 → `mode: flash` 0.05. A tinted frame = `paper: [255, 60, 40]` or the
  effect's colour. THE OWNER (2026-10-25): frames are OPTIONAL - "not everything needs impact frame ... impress me
  with the effect itself"; when a hit has them they must LINE UP with the shot on screen (`camera: "none"` = the
  live view; re-cropped / re-framed frames that do not match the attack read as weird). Where a big hit earns them,
  the `impact_frames` PART —
  `"use": [{"part": "impact_frames", "as": "<hit>", "at": "<beat>", "point": "<where the hit is>", "palette": {"accent": "<the effect's colour>"}}]`
  (four drawn frames + the white-out, 0.32 s, inside the hit's hitstop: a = the beam as a wedge + a spiky star + the
  rig's silhouette with a rim light from a low camera; b = black paper, white line art, bold lines, close-up;
  c = pure calligraphy (no scene: clouds, strokes, masses); d = wide, the wedge and star with perspective lines
  on the beam's far end; paper / ink per frame are palette names paper_a..ink_d, so `palette: {"paper_c": [255, 60, 40]}`
  tints a frame red; mute "*.white" / "*.frame_d" to drop one). A WORD is never in the default frames: the owner
  rejected a generic "DON!!" — a call-out is OPT-IN, and when asked for it is the ATTACK'S NAME in a deadly face
  that slams in with real exaggeration and then hands over to the attack: the `attack_call` part
  (`{"part": "attack_call", "as": "call", "at": "release", "point": "muzzle", "text": "STARBLADE", "sub": "HOLY SWORD", "palette": {"accent": "gold"}}`).
  A text frame is a DESIGNED TITLE CARD (the research: Demon Slayer's calligraphy on a brush band, manga SFX
  lettering, fighting-game cut-ins): the word is an ORIGINAL GRAPHIC — a heavy clean scaffold face (Impact by
  default) skewed into the motion, cut through by the blade, the glyphs jittered, a small spaced subline above —
  on a diagonal BAND with torn edges and streaks in the third of the frame away from the hit (`textPos: "band"`),
  the rig's silhouette beside it; SLAM motion over three frames: ENTRY (band + name slide in along the band, the
  trailing letters lagging, a 1.5x smear, the frame punched) → CONTACT (overshoot + squash, shake, splatter) →
  SETTLE (inverted, the attack's star and wedge begin); the face is split-toned (a light tint on top, the accent
  below) with a black outline and hard shadow, a glint sweeps the accent half on the contact frame, motion lines
  trail off the letters on the entry frame, an accent edge runs along the band, and a GHOST word (`ghost: "聖剣"`,
  Yu Gothic) stands hatched in the band's contrast colour behind the name. Every lettering knob may be a CURVE over
  the frame's life (`[[u, v], ...]`, u 0..1), so the card MOVES: the band whips in (`bandOffset`), the name slides
  after it (`offset`) smeared (`stretch`) and overshooting (`scale`), lands with a squash (`squash`), the glint
  sweeps (`glint`); two frames of 0.09 s are enough — a word that stands still for 0.07 s reads as a slide.
  THE OWNER'S FAVOURITE (2026-10-11): the name IS the impact frame — `lettering.cover: true` makes a full-screen card
  (`cardColor`), the name huge across it, torn (`rough`), blood running off the letters and spattered around
  (`drips`, `blood`); the blade's slash line flashes across (`cutFlash`), then the card is CUT (`cutAngle`): the
  halves tear apart (`gap`, up to 4), fly off to their sides (`slide`) spinning away (`spin`), sparks and blood
  chips in the gap — and what they reveal is the frame's own drawing (the silhouette, the wedge, the star). The
  `attack_call` part does it in 0.28 s (CARD 0.12 → BREAK 0.16): the cut is a demon's CLAW — `claws` parallel
  slashes `clawSpacing` apart, zig-zag cracks (`jag`) that CRAWL across the card first (`crawl` 0..1 with
  `cutFlash`), then every strip flies its own way and SHATTERS into shards (`shatter`) that spin off. Then
  `impact_frames` straight after, under ONE hit-stop (up to 0.8 s): no world time between the name and the hit.
  The owner loved the rip and asked to SEE it longer: the RIP is four 0.08 s frames whose curves continue one global
  tear (gap / slide / spin / shatter sampled per frame) while the card flickers black → white → blood red → white
  (the hit's drawing underneath alternating paper and line art); the gap opens slowly so the word stays readable
  until the last frame, the strips leave only at the end. LINGER (the owner: "make me feel the dread"): a hit-stop
  takes a `span` — the preset seconds of frames it plays through — shorter than its `hold`, so the frames play in
  slow motion while the world stands still (Starblade: hold 1.8 s over span 0.97 s; the card 0.20 + rip 4 x 0.11 =
  ~1.2 s real, the hit's frames ~0.6 s real). Holds cap at 1.8 s; a part `use` can also take `slow` (its times and
  lives stretched). The card is centred on the SCREEN (it ignores the frame's zoom toward the hit; it keeps the
  shake) and the word is ALIVE (`distort`, a curve): a heat ripple runs through the letters, rows glitch sideways,
  the word breathes, a blood echo trails it — animated by the held clock, on 24 fps ticks. The name must GRAB the
  viewer (the owner; NOT a literal spotlight): `reveal` stamps the letters in left to right, the newest one burning
  white; `spot` (the pull) converges ink speed lines on the word from the edges and crushes the edges to black;
  `scale` pushes the word in toward the viewer while it holds.
- **Pacing for dread** (the owner: "you should feel 'oh yeah, I'm gone' from your chair"): `timewarp: [[t, rate], ...]`
  is the clock's speed over the effect's time (rate 0.05..1; beat names allowed; player AND engine). Starblade: the
  gather tightens (1 → 0.6), the swing falls in bullet time (0.18–0.2: ~2.9 s real), the name + hit hold 1.8 s, the
  black ball's silence crawls (~0.5: ~3 s real), the blast's frames linger (hold 0.9 over span 0.36) and the blast
  unfolds slowly (0.25 → 1), then the aftermath in real time; low drones under the gather and the silence. The
  owner then asked "a bit quicker": every timewarp rate x1.3, the name hold 1.5 s — ~18 s.
- **Pillars are beams of racing light, never a mesh tube** (a translucent tube reads as a plastic can): `holy_column`
  (the `flow` recipe at high contrast, scrolled upward fast) in two crossed copies over a thin bright core, plus
  fire climbing the column (`blast_fireball` sprites rising). **Explosions are a simulated fireball** (`blast_fireball`:
  `fire_sim` with `emitter_z` ~0.1 so it bursts mid-air, `temperature_k` ~2200 and a gold `tint` for a white-gold
  core, low `flame_smoke`) plus a rolling dust wall (`dust_dome`: `smoke_sim`, strong vorticity, warm dust) spawned
  on a ground ring. Dome-shaped sim flipbooks must stay UPRIGHT (`rotation` ±12°): spun at random they read as
  wedges. After baking new textures, rebuild the play bundle (`kit vfx play`), the bundle lists textures.
- **No hard edges, ever** (the owner: "they look cut off, like barriers"). The four causes, all measured and now
  guarded: (1) a beam's ends — every beam fades in and out over `softEnds` (default 0.12 of its length; 0 = a hard
  cap) in player AND engine; (2) a beam strip's sides — the finish rolls off the sides of every wrapping strip
  (`post.side`, 0.2) and the gate `soft_sides` fails a strip whose edges are not dark; (3) the floor slicing a
  sprite — Roblox has no soft particles, so ground-level blast layers take a `zOffset` (studs toward the camera;
  the player now does the same push, not only draw order); (4) a flipbook cut at its cell — `not_clipped`: widen the
  sim's `frame`, keep a rays origin inside the cell (`origin`, `below`, `reach`).
- **A sheet needs a flipbook.** A 4x4 texture on a sprite without `flipbook` draws all 16 frames at once: a grid of
  little copies (Starblade's "white blobs" round the blast were a flash and a dust wave doing this). The validator
  now refuses it.
- **Magic circles (Fate)**: textures from the `circle` recipe (rings, star polygons, rune / Greek / Latin text bands,
  ticks, satellite circles, dots), drawn on a mesh `disc` with `params.planar: 1` (without it the texture wraps
  round the disc and turns into spirals). Cast them: an overshoot scale (0 -> 1.22R -> R in 0.12 s), a hold, a flare
  out. PLACE them, never scatter: one big circle under the caster, a few stacked through the pillar, a ring of
  satellites round the main rim cast in order, an arc of standing circles behind the caster (`aim` at it), a barrel
  of circles down the line the attack fires through.
- **A black hole is born from the strike**: it sits exactly where the beam ends (the beam's `to` IS the hole), it
  grows while the river pours in, then implodes into the detonation. The `blackhole` recipe renders it (black core,
  tilted swirling disc, lensed arc, photon ring; loops). Keep it off the floor (the floor cuts a big sprite) and keep
  the camera far enough that a 256-px frame is never magnified 10x. Its impact frames draw the hole too:
  `impact_frames_void` (draw knobs `void` and `crack`).
- Mesh layers take `rotate`, not `rot` (an unknown key is silently ignored). Beams take `curve` + `curveAxis` (the
  player now draws Roblox's Bezier). Debris takes `shape: "rock"` (faceted stones built at runtime) and Neon = hot.
- **Sims dissolve, they do not fade** (how AAA packs do it: a grayscale erosion map, not alpha). Fire and smoke
  sims take `post.erode` in the finish (a noise threshold eating the puff from its thin parts inward, a hot edge on
  the cut; the threshold is relative to each frame's densest point) and `sheet_end` (0.6: the sheet ends while the
  puff is still dense, the erosion finishes it). A sim's `emitter_z` / `temperature_k` / `tint` shape the fireball.
- **`squash` without `"orientation": "VelocityParallel"` stretches every sprite straight UP on screen** — it reads
  as rain. Streaks that converge on a point need the velocity orientation.
- **A black hole reads by its rim, not its black**: a black core + a tilted (`rot`) accretion disc + a camera-facing
  ring sprite (never a flat disc seen edge-on) + crackle, and the world dimmed (saturation and brightness down).
- **Impact frames may invert the palette** for the second hit (black paper, white ink, a blood-red frame): the
  blast reads as a different beat from the swing. Check them on the REAL time of the hold, not on the effect clock.
  `lettering: {skew, cut, stagger, stretch, squash, offset, scale, tilt, band, bandLines, bandColor, bandOffset,
  sub, ghost, ghostFont, split, glint, trail}`; `textSize` in screen heights, `textRot`; then `impact_frames` at +0.21 under
  TWO hitstops (0.22 + 0.36; a hold is capped at 0.5). Never a novelty face floating mid-frame — the gate
  fails a hitstop hit without frames (`frames_at_hits`) and a frame outside a hitstop (`frames_in_hitstop`). The
  viewer draws the frames live from any camera; the GAME gets them baked: `lune run kit vfx play <preset> --frames
  --views player` (the page draws each frame once, kit/vfx/frames.py writes plate specs `frame_<preset>_<layer>` +
  `assets/effects/frames/<preset>.json` + the contact sheet `build/vfx/booth/<preset>_frames.png` — LOOK at it; then
  `kit vfx`, then `kit upload --only frame_<preset>_`); Vfx.luau hands
  the map to VfxCompose, which gives each frame layer its `image` in-game (one camera's drawing, every view).
  THE DRAWING (without it the frame is a flat negative — owner): `exaggeration` (master) and
  `draw: {warp, grow, smear, outline, hatch, splatter, zoom, shake, flash, lineart, boil}` — a zoom punch and
  jitter on the hit, every edge noise-warped and re-rolled per frame (line boil), the energy grown and smeared
  away from the hit, Sobel outlines (`lineart` = outlined + hatched silhouettes for the dark frame), broken speed
  lines, hatching in the mid band, ink splatter heavier near the hit, a jagged white mass (`flash`, screen heights)
  at the hit in the light frame. Give every frame of a sequence different knobs (light: flash + hatch; dark:
  lineart + splatter; calligraphy: no outline, exaggeration 2+). Engine: paper = fog at zero range, silhouettes =
  Highlight fills on the rig models, lines = a ScreenGui image at the focus; the energy marks and the drawing are
  player-only until measured in the booth. `image` (a
  full-screen plate) and `ink | flash | white | black | mono` (grades) remain for special cases.
- **Slashes are asymmetric**: a sharp leading edge and a wider, stretched trailing edge (Genshin uses a 3D crescent
  mesh whose tail is pushed back by a vertex shader; the `slash` recipe draws the same thing as a flipbook). Keep the
  palette narrow; push the contrasting colour to the centre of the slash.
- **Impacts inherit the swing**: orient the impact burst by the weapon's direction and give its particles a share of
  the slash's velocity; "manga action lines" / impact stars on camera-locked planes sell the hit.
- **Hard-edged vector shapes beat soft gradients** for anime: fire as stacked jagged shapes, light as cel bands
  (`post.color: "cel"`, `bands` 2-3; `cel_wedge`, `light_blades`, `slash_cel`, `cel_puff`).
- **Timing**: cut particle lifespans in half from your first instinct; erosion that ends slow and linear reads as
  mush; the hit is instant, the build-up is long.
- **Vetted packs in the forge** (`"recipe": "import"`): Kenney Particle Pack 1.1 (CC0: 80 x 512² sprites — slash,
  trace, flare, light, star, twirl, scorch, spark, muzzle, smoke...) as `kn_*`; Unity Labs HDR EXR sequences
  (Thomas Iché, CC0: explosions, fireballs, flames, wispy smoke, clouds) as `ul_*` — HDR frames go through the same
  glow / hot-core / alpha / sheet finish as a render. `source` (dir or file), `select {start, step, count}`, `cell`
  (resize), `crop`, `premultiply`. Record every pack in VETLOG.md (licence quote, hash, what was inspected).

## Blender recipes (`assets/textures/<key>.json`)
`{ "engine": "fx", "recipe": "...", "frames": 16, "grid": 4, "cell": 256, "samples": 32, "seed": 1, "params": {}, "post": {} }`
- `burst` — 3D spikes of light from a hot core (flashes, impacts, glints: `"spikes": 0` = a mote)
- `wind` — ribbons whipping around an axis (wind barriers, tornado starts, spin attacks)
- `dust` — lumpy LIT volumes billowing out and thinning (dust, smoke; `post.color: "gray"` = tintable)
- `blast` — an emissive volume exploding: white core, gold/amber rim, tongues (light / fire explosions, novas)
- `flow` — a seamless energy strip for Beams (`"wrap": true, "beam": true`; scroll it with `textureSpeed`)
- `crack` — a glowing fissure + branch cracks + scorch, seen from above (ground decals)
- `ring` — a shockwave from above: bright torn leading edge, a streaky wash inside, expanding (flat sprites:
  `orientation: "VelocityPerpendicular"`, `speed: 0.001`, `direction: "Top"` = lying on the ground)
- `wave` — a crescent wave of light, face-on, streaks trailing behind it (slash waves; fly it down a beam as a
  `VelocityPerpendicular` sprite with speed along the path)
- `rays` — god rays fanning up from a point (upright `FacingCameraWorldUp` sprites above an impact / a charge)
- `import` — frames from a vetted downloaded pack (`source`, `select`, `cell`, `crop`, `premultiply`); see above
- `smoke_sim` / `fire_sim` — OUR OWN simulated elements: a Mantaflow gas domain baked headless (Blender 5.2 bakes
  under a temp_override), lit by a key and a fill, rendered as a Cycles volume flipbook — a real billowing puff /
  a fireball with its smoke (one-shot: the inflow stops at `inflow_until`). Params: resolution, bake_frames,
  emitter, velocity, dissolve, render_density, key / fill, blackbody (fire). ~1-2 min each.
- `shockwave` — a 3D ground shockwave from a low angle: an expanding torus of light with a hot edge + a flash disc
  (reads as a wave with perspective; lay it flat under an impact)
- `gradient` — a pure glow strip (a gaussian across the width, no noise body): pillars, tubes, halos — a strip with
  a dim noise body adds up to a brown slab on a double-sided tube; this one does not
- `glyph` — a magic circle decal: rings, tick marks, a hexagram, runes (Segoe UI Historic on Windows; `font` for
  another .ttf), one still or a slow spin across the sheet
- `lightning` — jagged ribbon bolts from the top down with forking branches, a white core in a coloured glow;
  `strikes` bolts in turn across the sheet, flashing in, flickering, snapping out (chain lightning, thunder strikes,
  electric auras: `rate` + `flipbook` random start)
- `slash` — a sword's slash ARC drawn in from its start angle to its end (sharp leading edge, white core on the outer
  radius, tail thinning into streaks), then fading; `post.color: "cel"` = flat anime bands (`slash_cel`)
- `shards` — faceted crystal / glass / ice shards flying out and spinning, lit by facing + rim only (tint it: ice,
  glass, gems); one-shot
- `cel` — an anime cel puff: overlapping spheres shaded by facing + a baked key light, posterised by `post.color:
  "cel"` + `bands` (hand-drawn smoke, impact puffs; `solid: 1` keeps the silhouette hard)
`post`: `glow {bloom, radius}`, `streaks {count, length, strength, angle}` (star flares), `exposure`, `alpha`
(`glow` = brightness, `coverage` = the render's own), `solid` (0 = alpha from light only), `color` (`color` baked |
`gray` tintable | `cel` + `bands` anime cel shading). Recipe params: see `kit/vfx/fxlab.py` (each documents its own).
Blender is the default source. (Local AI — FLUX.2 klein is installed — is not wired into the VFX forge yet.)

`kit vfx` also writes `build/textures/_library.png` + `_library.md` (every registered texture: a frame, recipe, grid,
upload state, which presets / parts use it) — LOOK there and reuse before rendering a new element.

## Version-3 preset
```json
{ "version": 3, "mode": "burst", "duration": 7.5,
  "palette": { "gold": [255, 205, 96], "dust": [196, 172, 140] },
  "points":  { "muzzle": [0, 4.5, -3], "target": [0, 8, -298] },
  "booth":   { "motion": { "raise": 0.55, "swingAt": 2.45 }, "views": ["player", "side", "hero"] },
  "layers": [ { "name": "release_flash", "kind": "sprite", "at": 2.56, "point": "muzzle", ... }, ... ] }
```
Points: `[x, y, z]` (x right, y up, -z forward; `scale` multiplies), a name from `points`, `"target"` (the caller's
target overrides it), `"@anchor"` (a part / attachment the caller passes; follows it every frame) or `"@anchor^170"`
(170 studs along the anchor's +Y, a sword's length axis: a beam from `"@tip"` to `"@tip^170"` is a pillar standing
ON the blade that swings with the chop).
Every layer: `name` (unique), `kind`, `at` (s), `life` (s); sequences `[[u, v], ...]` run 0..1 over that life.
Preset-level `"hitstop": [{ "at": 2.6, "hold": 0.09 }]` stops the whole clock for `hold` REAL seconds at `at` (the
anime hit-stop: particles, beams, meshes and the camera feel all hold).
- `sprite` — ParticleEmitter, every engine property: `texture`, `count` | `rate` + `for`, `lifetime`, `speed`,
  `spread`, `drag`, `acceleration`, `size`, `transparency`, `squash`, `color` (palette names ok), `brightness`,
  `lightEmission` (-10..1), `lightInfluence`, `zOffset`, `orientation`, `direction`, `rotation`, `rotSpeed`,
  `lockedToPart`, `timeScale` (lingering layers 0.6-0.95), `shape {type Box|Sphere|Cylinder|Disc, size, style,
  inOut, partial}`, `flipbook {layout "4x4" | [cols, rows], fps, mode, startRandom, blend}`, `twin {...overrides}`,
  `point`, `aim` (+Y of the emitter points at it).
- `beam` — `from`, `to`, `texture`, `plane` camera (ribbon facing the camera) | up (a standing WALL of light, both
  faces drawn) | flat (a sheet lying along the path), `width` (seq), `taper` [start, end], `grow` (s for the front to arrive),
  `copies`, `widthSpread`, `jitter`, `curve`, `textureLength`, `textureSpeed` (number or [min, max]),
  `brightness` (seq), `fade` (seq), `transparency` (along the length: soft-start a beam with `[[0, 1], [0.04, 0]...]`).
- `mesh` — runtime EditableMesh (`ring disc tube cone sphere dome spiral arc` + `params`) or `Ball/Block/Cylinder`;
  `material` Neon | ForceField (draws its texture as a glowing pattern) | Glass | SmoothPlastic; `scale` (seq of number
  or [x, y, z]), `uvScroll` [u, v] /s, `spin`, `pivot` base | center, `aim`.
- `decal` (ground marks; `glow` > 1 = overbright), `light` (range <= 60), `debris` (kinematic rocks on the clock),
  `screen` (brightness / contrast / saturation / tint / blur / `bloom` boost), `impact` (white = stark contrast-stretched | black | mono |
  flash = a flat white-out, the ufotable frame; <= 0.3 s), `shake` (degrees), `fov` (degrees), `sound` (kit sound name: `kit sfx <name>` renders it, `kit upload --only build/sounds/<name>.ogg` makes it live),
  `glow` (turns `@part` to light).

## Composition (beats / parts / variants) — expanded before anything validates or plays (VfxCompose)
```json
{ "beats": { "strike": 0.0, "release": 2.6, "impact": 2.88 },
  "hits": ["release", "impact"], "hitstop": [{ "at": "release", "hold": 0.09 }],
  "use": [ { "part": "impact_blast", "at": "impact", "as": "impact", "point": "impactGround", "scale": 1,
             "palette": { "gold": "gold", "dust": "dust" }, "mute": ["flood"] } ],
  "variants": { "ice": { "about": "frost", "palette": { "gold": [120, 190, 255] }, "scale": 0.8, "mute": ["beam_*"] } } }
```
- **beats**: any `at` (layers, `hits`, `hitstop`, `use`) may be `"release"`, `"release+0.2"`, `"release-0.1"`.
  Retime a whole effect from one table; a variant may override beats.
- **parts** (`assets/effects/parts/<name>.json`: `palette`, `points`, `beats`, `layers`, `hits`; `kit new vfx <name>
  --part`): a reusable sub-effect. `use` copies it in — layer names `<as>.<name>`, times after the use's `at`, its
  points moved to `point` (a host point or `[x, y, z]`) and scaled by `scale` (sizes, widths, radii, speeds, spans,
  zOffsets too), its colours mapped by `palette` (part colour → host colour name or `[r, g, b]`; unmapped ones join
  the host palette as `<as>.<colour>`), `mute` drops part layers (globs). A part's layers may name host points and
  `"@anchors"` directly (`strike_air` rides `@bladeMid` / `@tip`). Parts validate on their own in `kit vfx`.
  Shipped: `strike_air` (a cut through the air), `impact_blast` (something huge lands), `impact_frames` /
  `impact_frames_void` (a hit's drawn frames; the void one draws a black hole bursting), `attack_call` (the name card),
  and the Starblade round-6 kit (owner: "genuinely your best work", 2026-10-12) — each one a proven showpiece:
  `holy_gather` (field of rising light + pillar + crown, 3.6 s), `fate_circles` (circles CAST round a caster: floor,
  rim ring, standing arc, pillar stack, sky), `circle_barrel` (circles down the line a shot fires through),
  `black_hole` (born where a beam ends, fed, sealed, imploding at 1.0 s — follow with `impact_frames_void`),
  `cataclysm` (flash, fireball mass, dome, shock ring, dust wall, mushroom, rocks; 0 = the burst), `crater_aftermath`
  (glowing fissures, fire, a fire-lit smoke column). Start an ultimate from them: `kit new vfx <name> --from
  fate_ultimate_kit` (the parts alone, recorded and gate-clean) or `--from starblade` (the whole cutscene).
- **An example travels with what it needs**: `kit promote vfx <name>` packs its parts, its textures' specs, the
  finished pictures of imported ones (the download folder never travels) and their uploaded ids into
  `kit/starter/vfx/_deps/<name>/`; `kit new vfx X --from <name>` copies back what the project lacks.
- **variants**: palette / beats / scale / mute / about over the host; `kit vfx play <name> --variant ice`,
  `kit vfx booth <name> --variant ice`, in game `Vfx.play("starblade@ice", ...)` (registered at load; every variant is
  validated by `kit vfx`). Palette swaps and scale presets are variants; the same effect, no copied JSON.
- Prove a refactor onto parts changed nothing: `kit vfx expand <name> [--variant v]` prints the expanded preset
  (what the game / booth / player receive) — diff it against the old one (layer names and point names aside).

## Packs and references — the commands
- `kit vfx import <dir> --prefix kn --pack "Kenney Particle Pack 1.1 (CC0)" [--alpha glow|coverage] [--color gray]
  [--cell 512]`: every PNG under the directory becomes an `import` spec (existing specs kept); then `kit vfx`.
  Imported so far: Kenney Particle Pack (80, kn_*), Kenney Smoke Particles (77, ks_*), Unity Labs HDR sequences
  (ul_explosion_light, ul_explosion, ul_wispy_smoke, ul_cloud). Every pack: a VETLOG.md row first (licence quote,
  hash, what was inspected). `build/textures/_library.md` lists textures by pack.
- `kit vfx refs <preset> <url|file|dir>... [--frames 6]`: stills into `assets/effects/refs/<preset>/` (git-ignored):
  images copied, GIF / WebP / video turned into spread frames + the brightest one, sources logged in SOURCES.md.
  Wikis refuse plain clients: the tool sends a browser user agent. The viewer's refs panel and `kit vfx judge` use
  that folder.
- **TEXT FIRST — what the attack IS (owner 2026-10-14: "vision alone isnt working out u need both vision and detailed
  text")**: `kit vfx refs lore <set> <wiki:Page | URL>... [--search "<words>" --wiki <fandom>] [--pages 6] [--about
  "<words>"]` digs the article text (MediaWiki API: the technique's page, the character's, the EPISODE pages where the
  scene is described; any https page's visible text), keeps wiki TABLES as sentences (the variant tables hold the visual
  facts: "In Bankai, the Getsuga Tenshō is black, can have its path controlled, and possesses explosively augmented power
  and speed"), skips trivia/other-media, and on off-topic pages keeps only sentences naming the subject. Facts tagged
  colour/shape/scale/power/motion/sound/variant -> `refs_measured/<set>.lore.json`; full text -> `refs/<set>/LORE.md`.
  `kit vfx refs brief <set>` joins them with the measured palette/shape -> `refs_measured/<set>.brief.md`: READ it, and
  build every fact (scale, speed, what it does to the world, how the variant differs) — cite them in the generator's
  docstring (example: `getsuga_bankai_v3.py`). `refs measure` warns while a set has no lore, and `kit vfx refs norms
  <effect>` rule 5 FAILS unless the generator quotes >= 3 of the set's lore facts (examples: `spirit_bomb_v3.py`,
  `kamehameha_v4.py`). Video-game skill-list lines are scored out of the brief; a proven mechanic (a tube stack) is
  reused and changed where the text says (2x the user), not reinvented.
- **The details decide quality (owner 2026-10-15)**: look at every ELEMENT close up, alone. Air / energy / fire is
  never a solid surface: every big mesh gets a detail texture (wind_streaks / wind_streaks_v for gusts, ki_wisp_streaks,
  ki_cells ...), soft edges (fadeIn / fadeOut / fadeSides) and an erode dissolve; rings that ride a flow are feathered
  mesh discs facing it; streak sprites come from a small volume at varied speeds, thin. `refs norms` rule 6 fails bare
  solid meshes. Example: rasengan.py's blow-out (gust shells + swirl + rings).
- **The outline as numbers (`kit vfx refs silhouette <set> --effect <name> [--times a,b]`)**: aspect, taper, flame
  tips on the top edge, notch depth, fill — measured on the uncut reference stills and on our render, with what to change
  in the mesh shapes. UNTRUSTED under 8 uncut stills (wiki stills are mostly close-ups) and when the subject shares the
  effect's colour (golden hair in a golden aura): read it, never apply it blindly.
- **Impact frames are for MASSIVE hits only** (owner 2026-10-14: "not everything has to have impact frames unless ur
  gonna make it really massive"). A slash release, a charge, an aura: no impact frame — a 2-frame tint/contrast flash at
  most. `beats.py` defaults to `--frame none`. One per effect, on the landing of a world-shaking attack (Black Flash, a
  Bankai Getsuga's explosion).
- **The reference loop (2026-10-14 — use it for every effect from a real source; never show the owner an uncompared
  render)**: `kit vfx refs wiki <set> <wiki:Page>...` (every image on whole MediaWiki pages via the wiki's API, e.g.
  `dragonball:Kamehameha`; a page with 0 images = a wrong title: the tool prints the wiki's real ones; image hosts
  allow-listed) -> `kit vfx refs rank <set>` (stills scored by effect-colour coverage, hue band found by itself; LOOK
  at the numbered sheet `build/vfx/refs/<set>_rank.png` and pick the frames that show the effect) -> `kit vfx refs
  measure <set> --pick 1,4,9,...` (luminance bands: share + colour, saturation -> `assets/effects/refs_measured/<set>.json`,
  committed) -> build to those numbers -> record -> `kit vfx refs compare <set> --effect <name>` (0-100 colour match +
  render-beside-refs sheet). Measured colours are what the frame SHOWS: additive Neon layers stack and wash out, so
  feed them pre-saturated (x1.6 yellows .. x2.4 reds/oranges) and keep whichever version compare scores higher.
  compare judges COLOUR only: shape and timing are still read off the sheet. Proven: Saiyan forms (Kaio-ken 55 -> 80.8,
  Blue Kaio-ken 88.7), Kamehameha 64.6 -> 86.8 (517 frames).
- **Flipbooks on meshes**: a mesh layer takes `"flipbook": {"layout": "4x4", "fps": 16, "mode": "Loop|OneShot"}` (its
  UVs step from cell to cell: VfxMesh `cell()`), and the `cards` shape (`params.count` crossed vertical planes through
  the axis) gives a drawn flipbook depth. `python kit/vfx/meshify.py <preset> [--as <new>]` turns every one-particle,
  camera-facing, emissive flipbook card of a preset into such mesh cards (the original is never touched; output
  `<preset>_meshaura`). The owner's favourite look is this HYBRID: meshes for volume + the hand-drawn flipbook for the
  anime silhouette (saiyan_ssj_3d); an all-mesh rebuild without the drawings was rejected.
- Effect generators (the Python that writes a preset) live in `assets/effects/generators/` beside their presets —
  never in `_scratch/` (git-ignored).
- **No-hands loop (2026-10-14)**: `python kit/vfx/autorec.py <effect>... [--views hero,cine,player] [--compare <set>
  --times 2.6,3.6]` records with a HEADLESS local Edge/Chrome (same score as a hand-driven recording; it tree-kills its
  browser — orphaned headless Edges once starved the GPU). `python kit/vfx/fit.py <effect> <set> [--times ...]` grades
  every colour (saturation x gain), records + scores each grade, keeps the best as `<effect>_fit` (UI Sign 82 -> 86.9,
  Mastered UI 58 -> 83.2, Spirit Bomb 73.5 -> 87.1). A SHORT effect needs `--times` (moments it is on screen).
- **Timing rules (research: Riot style guide, realtimevfx critiques, 80.lv)**: `kit vfx refs timing <effect>` reads the
  recording's luminance curve: an anticipation DIP right before the climax (a 0.05-0.12 s screen darkening), a SNAPPY
  climax (attack <= 0.25 s: the release lands in 1-3 frames), a SHORT dissipation (<= 40 %), climax contrast. Fix what
  it flags (Kamehameha v1 2/4 -> v2 4/4).
- **Stylized mesh motion**: mesh layers take `"step": 12` (the clock held on drawings: on twos, the anime cadence) and
  `"erode": [start, end, soft]` (a per-vertex noise dissolve instead of a fade — coarse on big triangles: no per-pixel
  shaders in Roblox; dense meshes or a baked eroding flipbook for crisp holes). `python kit/vfx/animepass.py <preset>`
  applies both to every mesh layer (new preset `<preset>_anime`).
- **Shapes added for references**: `corona` (sharp blades out of a sphere: energy balls, starbursts), `arc` with
  `vertical: 1` (a standing crescent flying +X: slash waves), `cards`, `spikes`, `bolt`; textures `ki_cells` (worley
  skin), `ki_rays` (streaks on a light floor). Black on additive layers: a toon SmoothPlastic mesh, OPAQUE, with no
  glow over it (bloom smears bright rims across it — the Bankai Getsuga still reads dark-pink: open).

## The viewer (`kit vfx play <name>`)
Impact frames in the viewer AND in a recording: the frames run on the HELD CLOCK — inside a hit-stop the world
stands still while the sequence plays through (frameTime = the preset time + the time elapsed in the hold,
deterministic by dt: a 60 fps record holds 0.18 s for 11 frames), and a frame shown during a hold is spent (no
replay when the world resumes). Record at 60 fps to see motion inside a frame (`--fps 60`); a true slow-motion
clip of a hit: the record page with `&slow=4&from=3.9&to=4.9&fps=60` (the clock steps 1/fps/slow, the video
stays 60 fps) — never slow a clip by repeating frames. Make every hit-stop as long as its frame sequence (the gate
`frames_in_hitstop`). `[` / `]` jump between the frames (paused on each), `H` holds every hit-stop 6x longer; a
held frame is composed once and blitted (no stutter). The server never exits
while it only serves; records and bakes run on another port (`--port 47812`) so the owner's viewer stays up.
Three panes. LEFT: the layer list by kind — M mutes, S solos, click selects; the inspector below shows the
selected layer's fields: `apply` = this page only, `save` = the field goes back to the preset or part FILE
(POST /preset) and the watcher reloads it. CENTRE: the viewport (drag orbit, wheel dolly, right-drag pan, R reset),
HUD, the booth picture-in-picture (B), a reference overlay (V), and a FREE CAM (`F` or the view menu: W A S D fly,
Q E down / up, shift fast, drag looks, wheel sets the speed; it starts from the current camera). RIGHT: Refs (the stills), Booth, Metrics (live
numbers, the brightness graph, the last recording's gate). TOP: variant switch (every variant is bundled beside
the base, same clock), view, speed, transport (space , . [ ] Home), loop (I O L), reset cam, `sheet` (a 4x4 contact
sheet of this view downloaded as PNG), record. BOTTOM: scrub + lanes (click select, double-click solo, shift-click
mute). Hot reload: saving the preset or a part on disk re-expands it through the kit and swaps it in, clock kept.
Click the viewport = which layers are drawn there (their emitter points projected, nearest first; click one to
select it); hover a layer row = peek (only that layer shows). `?` = the key help. `window.kitPlayer()` = the Player.

## Judging (`kit vfx judge <name>`)
Never grade your own effect. `kit vfx judge <name>` builds `build/judge/vfx/<name>/`: one sheet per view from the
Studio booth (the truth) and the player (calibrated), the metrics gate, the preset's intent and the owner's
reference frames from `assets/effects/refs/<name>/` (stills of the target look — ask the owner for them), plus
`PROMPT.md` with the rubric (readability, timing, shape language, colour, impact, polish, fidelity; weighted). Hand
the packet to a FRESH judge (a subagent on another model, <= 4 images), then `kit vfx judge <name> --record
verdict.json`: the verdict is validated (every axis, an overall, >= 3 located gaps naming a layer or a moment) and kept
as `assets/effects/judge/<name>.json` tied to the sheets' hashes — a new recording needs a new verdict. Fix the gaps
in order; re-record; re-judge. The number is the judge's; the score is not the goal, the look is.

## Runtime
`local Vfx = require(ReplicatedStorage.kit.Vfx)` — server `Vfx.broadcast(name, where, scale?, target?, { reach = studs }?)` (with a reach only players within it of the effect or its target are sent it; every event carries the server's clock, so a client that gets it late starts the effect where its clock would be, or not at all once it is over), client
`Vfx.play(...)`; v3 control: `local stage = Vfx.stage(name, cframe, { target = hit, anchors = { blade = part } })`,
`stage:freeze()` / `stage:resume()` (hit-stop), `stage:setTimeScale(0.3)` (slow motion), `stage.time`.
Published games using `mesh` layers: Game Settings -> Security -> "Allow Mesh & Image APIs" (owner ID-verified);
without it those layers skip themselves.

## Engine facts (measured in Studio — trust these)
The full page with every measurement and its capture: `kit/knowledge/vault/vfx/refs/engine-facts.md` (probe:
`kit/vfx/facts.luau`). The ones that change how you build (2026-10-16):
- Studio IGNORES an EditableMesh's per-vertex alpha (VfxMesh `fadeIn` / `fadeOut` / `fadeSides` / `erode`) and the
  alpha of its `TextureID` / `TextureContent`: a mesh shell draws its whole texture square, opaque. The player shows
  both, so player and booth disagree on mesh layers. Only a SurfaceAppearance (ColorMap + AlphaMode Transparency)
  gives a mesh alpha, and a game script cannot set ColorMap (Plugin capability): author them ahead, clone at runtime.
- Vertex RGB renders (Neon 253 -> 29), but black still occludes: darkening is not fading.
- Wobble costs ~0.25 ms of Luau per 697-vertex flame per frame: 60 wobbling layers = 14-17 ms = the whole frame.
- Highlight outlines work on runtime meshes; VfxMesh cards + `cell()` flip cells (0.017 ms a call).
- A Beam texture's VERTICAL axis runs along the beam, horizontal across the width (author strips upright).
- `FaceCamera = false` makes a Beam a ONE-SIDED wall: width along Attachment0's Y, seen only from its -Z side
  (`plane: "up"` draws both faces for you).
- `Players:CreateHumanoidModelFromDescription` works in edit mode; the rig's joints are AnimationConstraints
  (not Motor6Ds): pose by FK over the rig attachments (child = parent * a0 * rot * a1^-1) with parts anchored.
- Additive layers ADD UP: near the beam, glows + curtain + waves + halo + bloom go flat white. Keep the sprites
  that ride a beam few and small; judge from the camera that will be nearest.
- Particles do NOT draw EditableImage textures (accepted, invisible): upload real textures.
- An uploaded image is usable in Studio within seconds; preload (`VfxStage.preload`) or the first burst is lost.
- Attachments: parent first, then set `WorldPosition` (before parenting it is read as a local position).
- Studio edit mode ticks ~20 Hz when unfocused: the booth freezes on exact times, so captures stay correct.
