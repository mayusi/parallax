# Lessons — testing, playtests, performance

- 2026-10-17 (mayusi, Parallax): A gate that is green on one disk is not green: kit prove (a sandbox worktree of the commit) found six bugs no session's own verify could see on 2026-10-16/17 - committed-unformatted files, a test reading git-ignored _artifacts data, kit anim's re-arm-before-fold build order, an uncommitted asset-id registry, CRLF from a fresh checkout breaking byte hashes, and an empty mesh cache changing a preview. Prove the committed tree (lune run kit prove --selftest) before calling a lane done.
- 2026-10-17 (mayusi, Parallax): Compare TEXT by content, never raw bytes: git on Windows (core.autocrlf) writes CRLF into a fresh worktree while the kit's tools write LF, so a byte hash called 83 unchanged UI screens stale. Hash text with CRLF read as LF and accept either form from older manifests (kit/ui/vault.py same()).
- 2026-10-17 (mayusi, Parallax): In a proof sandbox, share build INPUTS (texture renders, the VFX mesh cache, package folders) and own the judged OUTPUTS (build/ui, vfx, animations, moves, worlds): an empty mesh cache rendered planetary_cannon differently from the library, a shared build/ui let another session's live renders leak in.
- 2026-10-17 (mayusi, Parallax): A runner built on unittest reports 'Ran 0 tests' as green for pytest-style files (top-level def test_): 12 anim files / 84 tests never ran in verify until the runner routed them through pytest. Count tests per file; a file with def test_ and zero runs is a hole.
- 2026-10-24 (mayusi, Parallax): PLAYTEST READS (anim lane, 2026-10-24): a served set's hits signal runs IMMEDIATELY in some places - its handler sees the state BEFORE Moves applies the hit-stop / reaction (measured: speed 1 in the handler, 0 with 0.150 s left one task.defer later); read post-hit state in task.defer, and never sample 'the next frame' for a short effect: a background Studio server ticks every ~0.16 s, longer than a 0.15 s hit-stop
- 2026-10-24 (mayusi, Parallax): A playtest's print() is not relayed by kit playtest run - put what you need to see in a t.check message (counts, times) instead
- 2026-10-24 (mayusi, Parallax): A RemoteEvent fired before a client connects a handler is QUEUED and handed to the FIRST OnClientEvent handler that connects - a second handler connected later never sees it (the networked cutscene test missed its own broadcast). A broadcast that must reach late listeners also stamps its state on the remote (attributes) for them to read; a test reads the stamp, not a second handler
- 2026-10-28 (mayusi, Parallax): Studio Play driven by MCP while the Studio window is NOT focused runs the client at ~6 fps (Heartbeat dt 0.167 s with nothing playing) and VfxStage clamps its per-frame step, so effect timings sampled by Heartbeat look 'frozen' or late - measure a 1 s idle baseline first, and check an effect's presence the same frame the call returns, not by wall-clock samples (vfx-gt 2026-10-28).
- 2026-10-29 (mayusi, Parallax): Studio MCP input for combat proofs: user_keyboard_input's 'MouseLeftButton' key does NOT register as a click, VirtualInputManager is not callable from execute_luau (lacks RobloxScript), and separate mouse/keyboard calls land ~1 s apart in unfocused Studio (7 fps) - a mixed click+key string (air combos) can't be driven at game speed; prove keys-only moves by input, and get Studio focused (or the owner's playtest) for click+key strings. A training map's dummies' HumanoidRootPart is ANCHORED (launches can't move them) - unanchor one for a juggle test
- 2026-10-30 (mayusi, Parallax): Studio Play tests: (1) focus the Studio window first - unfocused Play runs ~6 fps AND animation time runs ~2.5x slower than the clock, so any timing or chain-window test lies; (2) never require game modules with side effects (SwordFx, FPSController) from execute_luau in Play - it runs in its own VM and loads a SECOND copy (a duplicate SwordFx prewarmed 5 more EditableMeshes and blew the budget); (3) the MCP click tool manages ~1 click per 0.8 s - drive fast input through a Studio-only BindableEvent hook (e.g. Players.LocalPlayer.SwordTestPress)
- 2026-11-12 (mayusi, Parallax): A self-test needle must not be a substring of its fixture's own name: a build's summary prints the piece's name (… kit judge _selftest_texel_bar_need), so expectFlag {texel_bar} could not miss and expectSpared {texel_bar} could not pass. Name a fixture for what it IS (map_need), never for the check it exercises, and assert the needle's presence / absence in the summary by script once.
- 2026-11-20 (mayusi, Parallax): moves_hitstop polls track.Speed once per Heartbeat: in a Studio window drawn in the background (6 fps, 0.167 s frames) the move's 0.05 s hit-stop release (task.delay) can resume BEFORE the next Heartbeat the test samples, so a freshly opened window failed 'froze' / 'moved again' twice while two older windows with the same code and data passed (held 0.165 s); a live probe showed the freeze is real (the track's TimePosition held one frame at the hit). Before calling it a regression: run it in another window, or with the window in front; the measurement (event- or TimePosition-based) is the owner's call - a test is never edited to pass
- 2026-11-20 (mayusi, Parallax): Studio MCP (2026-11-20): execute_luau's HttpService is now refused for localhost in EVERY datamodel ('domain 127.0.0.1:8765 is not in the Assistant HTTP allowlist'; localhost too, HttpEnabled on or off) - the 11-17/11-18 recipes that served src/kit or a studio_model pack over http.server no longer run. Two ways that still do: patch a module in Edit by plain string replacement on its .Source (find, assert once, sub) for a small fix; or a real Script made in Edit that runs in Play (it uses the engine's own HttpService and DID fetch 127.0.0.1 with HttpEnabled = true - an unsaved scratch place only).
- 2026-11-20 (mayusi, Parallax): The Studio MCP's execute_luau runs in the PLUGIN's context with its OWN require cache: a table a test changes in a required module (a Meta entry, a wrapped function) is seen by other kit code required from that same execute_luau, NOT by the game's Scripts / LocalScripts (measured 2026-11-20: a Meta entry set from the MCP on the client never reached AnimRoot's watcher). A proof that needs the game's own scripts to see a fixture (a server-started cue every client plays) is game scripts in a scratch place + StudioTestService:ExecuteMultiplayerTestAsync (tests/playtest/two_players/anim_additive.install.luau).
- 2026-11-20 (mayusi, Parallax): Roblox styling in the engine (2026-11-20): a StyleRule's value is read with inst:GetStyled(prop) - the property itself keeps the instance's own value (Rotation read 0 while styled 7); a StyleQuery turns active (q.IsActive) ONLY parented under the styled GuiObject (in the StyleSheet, under a rule or the StyleLink it never does); '@Name' selects the object the query sits under, so its nested rules need '> X' or '>> X' (a bare '.KitTitle' under '@Name' matched nothing). tests/playtest/ui_style_query holds both the kit's layout (red) and the engine's (control).
- 2026-11-20 (mayusi, Parallax): A playtest that plays a VFX swarm must put it IN FRONT of the camera: VfxStage leaves a swarm far from the camera where it is (VfxBudget.swarmCulled) - a test effect at (-60, 520, -900) never moved a pellet and its floor.onBounce looked dead (0 bursts); 20 studs ahead of the camera it threw 6 of 6 bursts at the floor.
- 2026-11-20 (mayusi, Parallax): world_traversal playtest: 'No OnInvoke handler / Target is not reachable' on execute_luau to DMN_ID_PLAYSERVER is a stale-window timing issue. The kit's poll for 'Server' in get_studio_state passes but the MCP plugin's OnInvoke handler in that window is not yet registered. Fix: open a fresh Studio window (Start-Process RobloxStudioBeta 'path.rbxlx') and wait ~30 s for it to fully connect before running the playtest. The old window stays stuck even after stop+wait.
- 2026-11-21 (mayusi, Parallax): A Studio playtest that places its probes far off (base 800 studs away) silently skips anything the kit culls by camera distance (a swarm past VfxBudget.SWARM_CULL never updates, so its cost read -1): put the camera near the probe and restore it after. A check of the form 'n == 0 or all good' passes on nothing - require n > 0. The kit home's own project must map src/kit/server like every kit game (it did not: VfxDebris group never registered, 0 of 8). A background Studio window draws ~6 fps: front it (_artifacts/studio_x/front.ps1) before timing checks.
- 2026-11-21 (mayusi, Parallax): A VFX playtest must hand VfxStage what the game hands it: VfxCompose.expand(preset) first (src/kit/Vfx.luau). vfx_stage_parity's Glass check passed a raw tech = { haze } that VfxStage never reads, so no Glass part was ever made and the check stayed red whatever the haze mapping was; print the measured number, not the table, and prove a check bites by playing the old code once in the scratch window
