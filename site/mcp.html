MCP server

Parallax exposes itself as an MCP (Model Context Protocol) server over stdio. Any MCP-capable AI client connects to it, receives the kit's rules at start-up and can then drive every pipeline. This page covers the protocol, all tools, the start prompts, every supported client and how uploads work.

The server

Start command
connect writes it for you: cmd /c python kit/mcp/server.py on Windows, the machine's Python (python3 first) with kit/mcp/server.py elsewhere. Clients that take a pasted block get the script's absolute path. The server finds the project root from its own file.

Rules at connect

When a client sends initialize, the server returns a short preamble followed by the contents of kit/harness/AGENTS.parallax.md as the instructions field. Every client receives the same rules at the moment it connects — no per-client instruction file is needed, and no client needs to fetch the rules separately.

The preamble says that Parallax is enforced, not advisory: pipeline work (3D models, VFX, animation, worlds, UI, sound, gameplay systems, QA) is refused until the agent calls parallax_start with the lane and your request (prompt). It points to parallax_case for the request's contract and parallax_skill for the lane's full recipe, says every command ends with summary: and next_action: to act on, and that each lune run parallax <command> in the rules is also the parallax tool with those arguments.

Tools

Eight tools in total. The parallax tool runs any command; the other seven are shortcuts for the most common operations.

Call parallax_start first with the lane and the request. Pipeline work is refused until you do.

Start prompts

The server exposes a start-<lane> prompt for each of the nine lanes. Clients that surface MCP prompts as slash commands show these as quick ways to begin a session in that lane.

The nine prompts are: start-3d, start-vfx, start-ui, start-anim, start-world, start-sfx, start-code, start-qa, start-kit.

Each prompt tells the AI to call parallax_start with the matching lane first, act on its next_action: and work only in that department, leaving every other department's files alone.

Equivalent CLI:

lune run parallax start 3d --prompt "a mossy stone well"
lune run parallax start vfx --prompt "a fire slash effect"
lune run parallax start code --prompt "a double-jump ability"

Supported clients

Connect a client from inside your game folder:

lune run parallax connect <client>

Several at once: lune run parallax connect claude,cursor. To remove: lune run parallax connect <client> --remove.

Keeping configs in step

After an upgrade or when you add or remove a client, run:

lune run parallax harness

This refreshes the connected client's config and hooks. To check without changing anything:

lune run parallax harness --check

Uploads through the Studio MCP

Uploads use Roblox Studio's built-in MCP server and Open Cloud. No API key is needed: uploads use your own Studio login.

The full upload flow

  1. Run the upload command. From your game folder: 
    lune run parallax upload
    The kit screens every new or changed file through the moderation gate (banned words, blood/gore), then writes build/upload_plan.json — one entry per file with the exact open_cloud_invoke call, the file's absolute path and the required permission scopes.
  2. Your AI agent uploads each file. For each entry in the plan:
    1. Call open_cloud_invoke with that entry's call (the studio_id comes from list_roblox_studios).
    2. Poll GET /assets/v1/operations/<operationId> with open_cloud_invoke until done is true.
    3. Record the returned id: 
      lune run parallax upload --record <file> <assetId>
      The kit stores the id in assets/ids.json (and in the VFX registry for textures).
  3. After the last record call, the kit recompiles models and screens that use the new ids and prints the experience grant.

To see what is left in the plan:

lune run parallax upload --pending

To check the moderation status of a pending item:

lune run parallax upload --status
Uploads are permanent

Open Cloud cannot delete uploaded assets. Use the moderation gate before uploading and check --status for items going through Roblox moderation.

One-time setup: creator and universe

In the game's kit.config.json:

"upload": {
  "creator": "user:<your user id>",
  "universe": <experience id>
}

Your user id is the number in your roblox.com profile URL. "universe" is optional: it is the experience the uploads (audio above all) are granted to, so they play there; the creator still owns them. For group-owned games, use "creator": "group:<group id>".

Required Studio permissions

In Roblox Studio: MCP → MCP Permissions. Under Publish and manage assets, allow:

  • asset:read
  • asset:write
  • asset-permissions:write (only if audio should be granted to your experience)

Also approve your game project's build folder as an upload folder. Changes apply to the client's next request.

Studio must be open with a place from a published game (not a local, unpublished place) for Open Cloud permissions to work.

Headless uploads (CI, no Studio)

Set ROBLOX_API_KEY in your environment. The kit then uploads by itself without needing Studio open. Never paste a key into a chat or a file; always set it as an environment variable in your shell or CI system.

# set in your shell environment, not on the command line:
# ROBLOX_API_KEY=...
lune run parallax upload

Enforcement

The MCP server gate is one of the enforcement layers (see Enforcement). It intercepts every parallax tool call. If the arguments are a mutating pipeline command and there is no fresh session token, the call returns isError: true with an exact parallax_start call to make next.

A session is started by calling parallax_start with prompt (or by calling parallax_prompt). The session is valid for 4 hours. Calling parallax_start again starts a new session in the named lane.

The mutating commands are new, asset, make, cad, gen, optimize, vfx, anim, world, ui, sfx, move, net and upload; a lookup under one of them (for example help, list, --status) is not gated. Read-only commands (status, task list, lessons, case, help and so on) are always allowed.

For Claude Code and Gemini CLI, the client guard hooks (kit/scripts/parallax_guard.py) are another layer: they run before write and shell calls (and, in Claude Code, parallax MCP calls) and after writes. These hooks also check writes to pipeline paths and direct writes to the session token file.

Legitimate bypass

Add --maintenance "<why>" to a command to pass the session gate for real maintenance work. This works from the CLI and through the parallax MCP tool alike (the server passes any call whose arguments carry it), and the CLI logs every use with its reason for your review. Setting PARALLAX_ENFORCE=off also turns the session gate off.
