Roadmap

Parallax ships for Roblox today. This page describes the engine support plan, platform status and known limits in each pipeline. It reflects what the repo states; it does not carry promises or delivery dates.

What is engine-agnostic today

Roughly 70% of kit/ is not about Roblox at all. The engine-agnostic core includes:

  • Governance: the work board, lane sessions, PROMPT-X, the cases, the quality locks, verdicts and the knowledge vault, the CLI and MCP gates, the git hooks.
  • Content tools: Blender modelling, UVs, bakes, sculpt and CAD; the vision and audio tools; reference finding; the effect player and texture baking; animation authoring and its gates.
  • Engine-neutral outputs: FBX and glTF models with PBR maps, animated glTF clips (kit/anim/export_clip.py), OGG sound, world blueprints as JSON, interface specs as JSON.
  • Pure runtime rules: the *Rules modules, rate limiting, move data, effect budgets and validation in src/kit/ hold no engine calls.

The Roblox-specific layer is thin: the emitters that turn the neutral data into Rojo models and places, the Luau runtime wrappers around the DataModel, the Studio MCP bridge for playtests, and the Open Cloud uploads.

The engine seam

A project names its engine in kit.config.json (or parallax.config.json):

{ "engine": "roblox" }

roblox is the default and the only engine with emitters today. The values godot, unreal and unity are recognised and answered with a pointer to the roadmap in docs/ENGINES.md. Running lune run parallax doctor shows the active engine.

The planned directory layout separates the core from one emitter set per engine:

kit/
  core/        engine-agnostic: governance, PROMPT-X, vault, board, DCC, vision, audio DSP
  engines/
    roblox/    Rojo .model.json / .rbxlx, Luau remotes, the Studio MCP bridge, Open Cloud
    godot/     .tscn / .tres text compiler, glTF animation libraries, Godot CLI / MCP, GDScript or C# runtime
    unreal/    Unreal Python AssetImportTask, .umap / .uasset, Niagara / MetaSounds, Remote Control
    unity/     C# AssetPostprocessor and .meta, Prefab / UXML / USS, Unity MCP, a runtime package
runtime/
  core/        pure rules and state machines
  roblox/      today's src/kit/ Luau wrappers
  godot/       addons/parallax/
  unreal/      Plugins/Parallax/
  unity/       Packages/com.parallax.runtime/

Why Godot first

Godot's scenes and resources are plain text, like Rojo's model files, so the kit can compile them offline and check them in CI. Godot imports glTF natively, and the kit already exports glTF models, animated glTF clips and OGG sound. godot --headless runs playtests with no editor daemon.

Unreal Engine and Unity follow, behind the same MCP server and the same gates.

Also planned

The README's roadmap lists these, in no fixed order:

  • macOS and Linux as first-class platforms.
  • A one-step install of the MCP server.
  • The known limits: locomotion clips and input steering, water that breaks and sprays, a proven smoke route, a runtime prop player, and quality checks for town dressing.
  • Shared knowledge: opt-in syncing of lessons and golden sets between projects and teams.

Platform support

Windows 10 and 11
The primary platform: Parallax is "Windows first". The zero-GPU core runs on any Windows 10 or 11 PC.
macOS and Linux
On the roadmap as first-class platforms. Release 3.1.0 made tool discovery portable (Blender, COLMAP, Instant Meshes, the Python launcher), and doctor reports the Studio MCP per operating system.
Tier 4 (full 3D generation)
Needs CUDA 13, an NVIDIA GPU with 12–16+ GB VRAM, 32 GB RAM, Windows and MSVC 2022.
Note

Roblox Studio and its MCP server are needed for uploads and in-engine playtests. Studio runs on Windows and macOS only; doctor looks for the macOS bridge at /Applications/RobloxStudio.app/Contents/MacOS/StudioMCP, and on Linux it reports the bridge as unavailable.

Known limits in each pipeline

These are limits stated in the kit's own help and skill pages. They describe the current code, not a commitment to change it in a particular order.

Note

The literal --by owner flag below means you: the person who runs the kit and approves the work.

Known limit

sharpen makes a generated part's soft surface sharp, view by view, but it cannot fix a shape. Look at the shape from every view first.

Known limit

gen mv-shape and gen paint (Hunyuan3D-2) are for private assets only. The reason is the Tencent Hunyuan licence recorded in VETLOG.md, which limits where their outputs may be shown.

Known limit

vision angle and vision edit (Qwen-Image-Edit) are LOW TRUST: their pictures are generated, so look at them and never measure from them.

Known limit

Tier 4 (full 3D generation) requires CUDA 13, an NVIDIA GPU with 12–16+ GB VRAM, Windows and MSVC 2022. Lower tiers build with CAD, procedural scripts and vetted CC0 meshes.

Tip

The parts libraries (lune run parallax parts <lane>) file each lane's past parts by kind, with your verdicts and words on them. The more pieces you build and score, the more a new piece can look up.

Known limit

Effects are made and judged in the browser player (vfx play). vfx booth, which captures a preset in Roblox Studio, is off the VFX route: Studio only proves engine facts.

Known limit

The water simulation (vfx water) holds water's mathematics but was never matched to a real scene, and nothing in it breaks or sprays. vfx liquid is a side-view flipbook with no depth.

Known limit

Frame breakdowns (vfx breakdown) and the other clip tools use ffmpeg.

Tip

The vfx methods command lists the kit's method catalog. Use vfx methods --set <set> to plan which methods a new effect set's beats use before building.

Known limit

The authoring tools (key poses, strikes, cycles, rearm, the feel pass) work on R6. Each build also compiles R15 KeyframeSequences, and anim import retargets a real animation onto the R15 rig.

Known limit

A named animation build starts its clock: 30 minutes for a complex clip (the default), 10 for a simple one, 60 for a hero clip you approved. Past it, no change builds until you extend it with your words (clock --extend).

Known limit

A world errors above 10,000 parts and warns above 3,000 (heavy for mobile): merge pieces or use meshes.

Known limit

world look renders stations in Blender (Tier 1). world studio shows the same stations in Roblox Studio's own light and needs Studio open with its MCP.

Known limit

UI pieces start from real reference images, not words. The refs lock lives in the UI compile step.

Known limit

ui booth and ui bundle show a screen in Roblox Studio, so they need Studio running with its MCP.

Known limit

The SFX pipeline renders to OGG for Roblox.

Known limit

A new sound requires a reference you chose (approve sfx <name> "words" --by owner) or your synth-only waiver (--waive refs) before it builds.

Known limit

The sfx av sub-command uses ffmpeg.

Known limit

net generates Luau remotes for Roblox. Other engines' equivalents are the Code driver of the multi-engine plan.

Known limit

Fuzzing (fuzz) and mutation testing (mutate) run on src/shared modules only, not on server or client scripts.

Known limit

The docs command searches the Roblox Engine API locally using Studio's own en-us.json. It does not cover third-party libraries or other engines.

Known limit

Playtests (playtest run) are driven through the Roblox Studio MCP, so they need Studio installed and running with its MCP server enabled.

Known limit

The prove command checks out the committed tree into a sandbox. Uncommitted edits are not included.

Known limit

selftest reuses a case that was green at the same inputs unless you pass --no-cache (the cold proof). The cache is off by default in a linked worktree such as prove's sandbox.

Contributing

Each engine driver is its own piece of work with a clear neutral input and a clear engine output. Ideas, prototypes and pull requests are welcome. See docs/ENGINES.md for the full driver table and CONTRIBUTING.md for how to work on the kit.
