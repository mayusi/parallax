Hardware and models

Parallax runs on any PC and grows with your hardware. This page covers the five machine tiers, the AI models each one downloads, the runtime or environment each model runs in, and what they unlock in each pipeline.

Machine tiers

Each tier includes everything in the tiers below it. Steps 1–4 of Setup give you Tier 0. A lane on a lower tier takes the route that tier allows instead of failing.

A tier's vision setup command downloads weights only. Each model also needs a runtime, and every tab below says which one:

  • The kit's own Python: the python on your PATH that runs the kit. For models it needs PyTorch, transformers and safetensors, which no Parallax command installs (see PyTorch and runtimes).
  • The diffusers environment: a separate Python environment you set up from kit/gen/README.md.
  • The TRELLIS.2 environment: the 3D generator's environment, set up and compiled from kit/gen/README.md.
  • sd-cpp: stable-diffusion.cpp, a native program that the Tier 4 setup downloads.

AI models added: none. Vision models are Tier 2 and above.

Runtimes added

  • Blender 5.2 LTS: 3D modelling, UV mapping, baking, animation rigs, world and UI renders.
  • tools setup kit-python: adds two pinned wheels to the kit's own Python: vtracer (kit vision vectorize) and spandrel (kit vision upscale). spandrel also needs PyTorch and torchvision there.
  • cad environment: build123d on OpenCASCADE, for hard-surface CAD. Its own environment is in ~/.cache/roblox-kit/envs/cad, which also sees the kit's Python packages.
  • mitsuba environment: Mitsuba 3, a differentiable renderer the kit uses for fits. Its own environment is in ~/.cache/roblox-kit/envs/mitsuba.

Unlocks: 3D modelling, UV packing, baking, CAD boolean shapes, Mitsuba fits, animation rigs in Blender, world greybox renders, UI mockup renders. All without any AI vision model.

Install

lune run parallax vision setup

Downloads the 8 core models (~2.4 GB). An interrupted download resumes; every file is kept only if its size and hash match its pin. PyTorch, transformers and safetensors are not installed by this command (see PyTorch and runtimes).

AI models added: see the model registry filtered to Core. All 8 run in the kit's own Python (kit/vision/run.py; the upscalers through kit/vision/upscale.py). The on-demand clap-general sound model also runs there.

Unlocks: part cut-outs (kit vision cutout), part masks from a point or a box (kit vision mask), depth maps (kit vision depth), edge maps (kit vision edges), similarity ranking of reference images, picture upscaling (kit vision upscale). Used by the 3D, VFX, UI and world pipelines for reference analysis.

Force CPU

Set KIT_FORCE_CPU=1 to run these core models on the CPU (same results, slower). It skips the CUDA probe, so use it if your GPU driver faults on that probe. It applies only to the core models; the Tier 3 and Tier 4 models still need CUDA.

Read licences first

Each Tier 4 generator has its own licence; some restrict territories or uses. Read its VETLOG.md row before installing. TRELLIS.2 reads pictures through Meta's DINOv3 encoder, which is under the DINOv3 License (it has a trade-controls clause) and is gated: you need your own Hugging Face access and HF_TOKEN.

AI models added: see the model registry filtered to Gen. This tier adds 2 entries on top of the 20 below it.

Runtimes added

  • sd-cpp (stable-diffusion.cpp): the native CUDA 12 runner for GGUF models on Windows, launched from the kit's own Python. It runs qwen-image-edit.
  • Generator environments: TRELLIS.2, Pixal3D, Hunyuan3D-Omni, PartCrafter and Hunyuan3D-2, each set up from kit/gen/README.md.

Unlocks

  • Image-to-3D draft generation (TRELLIS.2): one picture in, a high-detail mesh with PBR maps out (kit gen).
  • Texture painting onto a kit-built mesh from a reference photo (kit gen texture).
  • New camera angles and edited versions of a picture (qwen-image-edit, kit vision angle / kit vision edit).
One GPU job at a time

Windows does not raise an out-of-memory error when VRAM is exceeded; the job spills into system RAM and runs 4–20x slower. Start generators only on an idle card.

LLMs and vision-language models

Parallax does not need a local text LLM. All reasoning (planning, writing, reviewing) is done by your AI client. The kit provides context (every command ends with summary: and next_action:) so any model can continue without reading the whole codebase.

When there is no local VLM

Where a local VLM would judge something and Tier 3 is not installed, the kit hands your AI client a packet instead: the pictures and a PROMPT.md with the exact questions. Your client answers, and the kit records that answer with --record. No lane is blocked waiting for a local VLM.

The local VLM

The local vision-language model the kit queries is Qwen3-VL-4B (qwen3-vl-4b, Tier 3). It is a 4-billion-parameter instruction-tuned model (bf16) run by PyTorch and transformers in the kit's own Python. Its uses:

  • kit refs inventory: lists every visible detail of a reference image with its bounding box, so your AI client can discuss it without seeing the image.
  • kit refs read: reads engraved or printed text in a reference image.
  • Yes/no relevance scores for text prompts, used when the kit reranks found parts (kit/tools/parts_rerank.py).

Tier 4's qwen-image-edit also bundles a vision-language model (Qwen2.5-VL-7B), but only as its text encoder, run inside sd-cpp.

Not a default

Qwen3-VL-4B is downloaded with --tier vision, not with the default core tier. Without it, kit refs inventory skips its VLM passes and your AI client answers the packet instead.

3D generators

The Tier 4 generators are set up through kit/gen/README.md. Each has its own Python environment and is installed separately after vision setup --tier gen.

The primary generator is TRELLIS.2-4B (Microsoft, MIT licence). It reads pictures through Meta's DINOv3 encoder, which is under its own DINOv3 License and is gated. One picture goes in, and a high-detail mesh with its own PBR maps (base colour, metallic, roughness) comes out. The kit cuts the result into moving parts, sets joints, runs all gates and kit optimize to Roblox's budget. A generated mesh has 100,000+ triangles; kit optimize takes it to the game budget.

TRELLIS.2 also has a shape-conditioned texturing mode: it paints base colour, roughness and metallic onto a given kit-built mesh from a reference photo (kit gen texture).

Known limits

kit gen texture paints at 512 only. The 1024 network (fetched since 2026-11-19) is used by kit gen --res 1024 for shapes, not by the texturing route. One photo means the sides it does not show are guessed. Colour detail covers panels and two-tone finishes, not fine lettering or engraving.

The other generators, all documented in kit/gen/README.md:

  • Pixal3D (kit gen views): a shape from 2–4 views with their cameras.
  • Hunyuan3D-Omni (kit gen omni): a shape held to a code-built blockout. Its licence excludes some territories; read it before you ship a mesh from it.
  • PartCrafter (kit gen parts): one picture to separate part meshes.
  • Hunyuan3D-2 (kit gen mv-shape, kit gen paint): private experiments only; its meshes are marked "private_only": true, and the kit refuses them in a public asset.

GPU guidance

  • One GPU job at a time. Windows does not raise an out-of-memory error when VRAM is exceeded; a job that outgrows the card spills into system RAM and runs 4–20x slower. Start generators only on an idle card.
  • Peak memory is PyTorch's reserved memory, not allocated. Call torch.cuda.empty_cache() between a generator's stages.
  • Driver fault workaround: if torch.cuda.is_available() crashes the process while the GPU still responds, restart the driver (Win+Ctrl+Shift+B) or reboot. For the current session, set KIT_FORCE_CPU=1 for the core vision models.
  • Blender OpenImageDenoise on the GPU gives the same render result about 5 times faster than the CPU path.

What doctor prints

Two commands check your machine.

lune run parallax doctor

Checks every Tier 0 tool (only a Tier 0 gap fails it), then each department's tools, listing any missing one with what it blocks. It works out your hardware tier: Tier 1 needs Blender, vtracer and the cad and mitsuba environments; Tier 2 the core weights; Tier 3 an NVIDIA GPU with 12 GB and the vision weights; Tier 4 the gen weights and the TRELLIS.2 environment. The weights are checked for presence and size only (--check --quick, no hashing). It prints:

machine tier: N (<tier name>)

Below Tier 4 it also prints what the next tier needs, then the engine line, and ends with summary: and next_action:.

lune run parallax vision doctor

Runs six core models on a small probe image (teed, birefnet, sam2.1-hiera-small, depth-anything-v2-small, siglip2-base and dinov2-reg-small) and reports the torch version, the GPU it found (or the CPU) and the time for each. A model that fails shows FAILED: <reason>, and the next_action: names the first failure.
