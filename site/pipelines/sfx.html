Pipeline

Sound

The sound pipeline makes Roblox sound effects — UI clicks, hits, explosions, weapons, abilities, and ambient loops — from real recordings layered with synthesis. Sounds are built in sets that share one sonic DNA, measured with an objective "ears" tool, matched to references you chose, judged by you in a listening booth, and synchronised with the hit in the engine. In-game they play as named events through the kit's Sfx runtime on the Roblox Audio API.

Tier 0 3 approvals 10 / 30 / 60 min clock

At a glance

Makes
Uploaded Roblox audio assets, waveform and spectrogram sheets, a checked events map (assets/sounds/_events.json), ambience zone files, and sound-on-picture clips (build/sounds/av/).
Hardware
Tier 0 All synthesis, gates, the listening booth, sheet rendering, and upload — no GPU needed.
Tier 2+ LAION CLAP semantic search over the audio library (optional; also works on CPU with KIT_FORCE_CPU=1).
Your approvals
Three: your direction pick (stage 0) before any sounds are built, your reference picks (stage 1), and your verdict in the listening booth (stage 6, scored 0–10 with words). A score never approves a sound; you do.
Clock
10 min for a simple sound, 30 min for a complex sound set, 60 min for a hero sound (requires kit approve). Past the budget, no change to the sound can be built (the sound as it was can still be rebuilt and played); extend only on your words via kit clock sfx <name> --extend <minutes> "<your words>".
Results land in
build/sounds/sheets/ (visual sheets), uploaded audio IDs in assets/ids.json, build/sounds/av/ (sound-on-picture clips), src/shared/<World>Ambience.json (ambience zones).

The flow in one line

direction (you pick) → refs (you pick in the booth) → identity (measured ranges per class) → design (layers with roles) → match (CMA-ES fit to reference) → sheet (waveform + spectrogram; you look) → booth (you score) → sound on picture → runtime (catalog + playtest) → upload

The stages

  1. 0
    Direction you approveGenerate three sonic directions for a place or weapon set; you pick one before any sounds are built.

    Every original place or weapon set starts with a direction, not a sound. The command reads your intent and produces one idea, six or more references from three or more media, three sonic pillars (what this place always has in common), bans (what it must never be), and three full directions that differ on at least two axes: space, source, density, and mood. Each direction becomes a sketch — a short bed, a few events, and one convolution space using a real impulse response — played back so you can hear the difference before committing to a build.

    kit sfx soundscript lays the place's sounds out in journey order: loudness, density, brightness, and space across the player's route.

    Runtime places can be alive: kit.WindVoice plays tonal wind driven by cavity physics and the global wind value; kit.GustEvents fires rare audio moments on real gusts; kit.EchoZones answers the player's own steps with a late reflection. All three are data-driven from the world's ambience JSON.

    lune run parallax sfx direction SwordSounds --new   # generate three directions
lune run parallax sfx sketch scene.json             # build one direction as a sketch
lune run parallax sfx board                         # play sketches; pick one

    Produces: Direction spec and three sketch files ready for the board.

  2. 1
    References you pick in the boothPick up to three reference recordings per class; they become the target the pipeline matches against.

    References are the ceiling of what this set can sound like. Up to three recordings per class (hit, swing, UI click, and so on) are chosen by you in the listening booth after the kit proposes candidates. Candidates come from kit sfx find: a keyword search over the library, or a semantic description search using LAION CLAP if you have fetched the model (kit vision setup clap-general) and indexed the library with kit sfx clap index.

    References are stored in assets/sounds/references.json. Measure-only references are indexed with --licence measure-only and are never shipped to Roblox.

    lune run parallax sfx find "heavy metal impact"       # keyword search
lune run parallax sfx find "a dense thud with tail" --describe  # CLAP semantic search
lune run parallax sfx listen candidates               # play candidates; you pick refs

    Produces: Reference entries in assets/sounds/references.json.

  3. 2
    IdentityMeasure the references and derive the game's sonic identity: measured ranges per class of sound.

    The kit reads your reference recordings through the ears tool and derives a sonic identity at assets/sounds/identities/<id>.json: for each class of sound (a hit, a swing), the measured range of each trait, plus bans. A sound outside a range gets a warning; a banned source in a recipe is an error.

    Traits measured: loudness (lufs), punch (crest_db), brightness (brightness_hz), tail length (tail_ms), attack (transient_ms), and the sub and high band shares.

    lune run parallax sfx identity MyGame --from <reference files> --class hit   # derive the hit class
lune run parallax sfx identity MyGame --check SwordHits                       # check sounds against it

    Produces: assets/sounds/identities/<id>.json.

  4. 3
    DesignWrite the layer recipe: sources with roles, envelopes, filters, and the set's shared DNA.

    A sound is a JSON file at assets/sounds/<name>.json describing a set of layers. Every layer has a role: one of transient, body, sub, mechanical, tail, sweetener, or air. The role is enforced: a sub layer with no sub-bass energy is a build error.

    Layers can use:

    • Samples — "sample": "lib:kenney.impact_metal_1" (a CC0 or royalty-free recording from the indexed library; multiple values in an array for round-robin variation).
    • Noise synthesis — a generated noise burst. Short bursts must carry a seed value; without one, the character can drift wildly between takes (an unseeded 90 ms brown thud was measured swinging from 8% to 38% sub between takes).
    • Modal synthesis ("source": "modal") — a struck resonant body defined by frequency, decay-rate, and gain triplets. Good for metallic rings and tonal impacts.
    • Karplus-Strong synthesis ("source": "karplus") — plucked strings or chains.

    A set is a JSON file at assets/sounds/sets/<set>.json that groups related sounds (a light hit, a medium hit, a heavy hit) under shared DNA — reverb tail, sub weight, brightness band, and a single loudness level. The set gate enforces that the DNA is consistent across members.

    lune run parallax new sound sword_hit_metal      # create a new sound spec
lune run parallax sfx set SwordHits              # build a sound set

    Produces: assets/sounds/sword_hit_metal.json (spec), processed audio in the build cache.

  5. 4
    MatchUse CMA-ES optimisation to fit the sound's gains, envelopes, and filter cutoffs to the reference.

    The match step runs a CMA-ES (Covariance Matrix Adaptation Evolution Strategy) optimiser against the ears measurements of the reference you chose. It adjusts gains, envelope parameters (attack, decay, sustain, release), filter cutoffs, and pitch to bring the ears numbers closer to the reference.

    The rule: find one difference between the current sound and the reference, then make one edit per role to close it. Never chase a score — look at the specific measurement that is off and fix only that. Iterating this way keeps changes legible and prevents over-fitting to numbers.

    lune run parallax sfx match sword_hit_metal --to ref_metal_impact

    Produces: Updated spec parameters; rebuild triggers automatically.

  6. 5
    SheetRender the waveform, spectrogram, and ears measurements alongside the reference; you look at it.

    The sheet is the evidence you read. It shows the waveform, a full spectrogram, loudness over time (momentary loudness, 50 ms window), and brightness over time — all rendered alongside the reference for direct comparison. Because the pipeline has no ears of its own, the sheet is the primary verification tool.

    Look for:

    • Sub energy on impact (first 150 ms under 120 Hz matches the reference).
    • Tail shape (brightness darkens naturally in a real recording; a synthesised tail often stays flat).
    • Transient sharpness (10-to-90% rise time).
    • Level relative to the reference (one loudness per class ± 2 LU).
    lune run parallax sfx sheet sword_hit_metal --ref ref_metal_impact
# open build/sounds/sheets/sword_hit_metal.png and look at it

    Produces: build/sounds/sheets/<name>.png.

  7. 6
    Booth you scorePlay sounds to you in the listening booth; you score 0–10, pick the best, and give words.

    The listening booth is a local server on 127.0.0.1:8791. kit sfx listen starts it (or reuses it) and returns at once; it stops after 2 hours idle or with --stop. It presents sounds in a blind order (or named, with --blind removed) so you can compare candidates without bias from prior rounds.

    Important rules of the booth:

    • A score never approves a sound; you do, with your words about what you heard.
    • Judge sounds in sync with their animation and effect, not in isolation. A hit sound that rates well alone may fall flat on its picture.
    • The taste profile (kit/knowledge/sfx_taste.json) learns what you reward once six or more verdicts exist. It is shown as a report beside each take's measurements, never as a gate — and it only predicts after you have given your verdict, never before.
    Watch out

    The booth server must run outside the Lune job, or it dies when the command ends. The kit launches it that way for you (WMI breakaway and a per-launch token), with Host and Origin checks.

    lune run parallax sfx listen sword_hit_metal --blind   # play blind
lune run parallax verdict sound sword_hit_metal 8 "heavy, clean tail, good sub on impact"

    Produces: Verdict entry in the vault and the taste profile update.

  8. 7
    Sound on picturePut the sound on its picture and watch it in context.

    A sound is never complete until it is in sync with its picture. kit sfx av lays the sound onto a capture of the action (a VFX reel, an animation strip GIF, a gameplay clip) starting at --at seconds, and writes a clip you watch. It does not measure the timing for you: you judge it by eye and ear.

    Each --cue name@seconds adds another sound at its own time, so a whole score can sit on one clip. The swing-lead rule (a whoosh leads the first active frame by 50 to 300 ms) is checked on the move data by kit move: see the Gameplay systems pipeline.

    lune run parallax sfx av sword_hit_metal --video capture.mp4 --at 1.42

    Produces: build/sounds/av/<name>.mp4 for you to watch.

  9. 8
    RuntimeMap sounds to game events in the catalog; prove the events fire correctly in a Studio playtest.

    Sounds are played in-game as named events, not by asset ID. The event map lives in assets/sounds/_events.json. kit sfx catalog validates it: every event must name a sound that a recipe or set makes, all bus names must be known, and blend keys must be numeric.

    After the catalog passes, prove it in the engine: a Studio playtest fires the events and reads the Sfx.stats() report (voices, voices per bus, dropped sounds) to prove the voice limits hold in the engine.

    lune run parallax sfx catalog                           # validate _events.json
lune run parallax new playtest sfx_smoke                # scaffold a playtest
lune run parallax playtest bundle sfx_smoke             # bundle for Studio MCP
# ... drive it through the Studio MCP ...
lune run parallax playtest record sfx_smoke result.json

    Produces: a checked assets/sounds/_events.json (the catalog also lists sounds not uploaded yet), playtest result in build/playtest/.

  10. 9
    UploadUpload the set to Roblox and grant it to the target universe.

    Upload is scoped to a set: kit upload --only assets/sounds/<set>. After upload, check moderation status with --status. Uploaded sounds must be granted to the target universe before they will play in the game — the upload command handles the grant automatically.

    Private audio plays only where it has been granted. A Creator Store asset ID can be restricted per experience, so always check moderation status after upload.

    lune run parallax upload --only assets/sounds/SwordHits   # upload the set
lune run parallax upload --only assets/sounds/SwordHits --status   # check moderation

    Produces: Asset IDs recorded in assets/ids.json.

The ears tool

The ears tool (kit/audio/ears.py) is the pipeline's measurement instrument. It converts audio into numbers you can read and compare. Because the pipeline itself cannot hear, the ears output is the only evidence for decisions at the match and sheet stages.

MeasurementWhat it meansTypical range
lufsBS.1770 gated loudness (a 1 kHz sine reads −3.01 LUFS on this meter).UI: −20…−12 · Hits: −18…−14 · Swings: −20…−17
true_peak_dbfsThe highest reconstructed sample peak; must stay at or below 0 dBFS.≤ 0 dBFS
crest_dbPeak-to-RMS ratio, a measure of punch.—
transient_msTime from 10% to 90% of peak amplitude — the attack sharpness.—
attack_msTime from silence to peak.—
tail_msTime from peak to −40 dB — the decay length.—
brightness_hzSpectral centroid of the full sound.Booms < 300 Hz · Hits 300–1200 · UI/swings 1200–3500 · > 3500 harsh
centroid_start_hzSpectral centroid of the first 50 ms — the attack brightness.—
centroid_end_hzSpectral centroid of the last 100 ms — the tail brightness. Real tails darken; synthetic tails often stay flat.lower than start in real recordings
fluxFrame-to-frame spectral change — a measure of texture and movement.—
onsetsCount of detected onset events (1 for a hit, many for a rattle).—
sub_shareEnergy fraction below roughly 120 Hz.—
low_shareEnergy fraction in the low-mid band.—
mid_shareEnergy fraction in the mid band.—
high_shareEnergy fraction above roughly 4 kHz.—
Note

BS.1770 gated loudness on a sound shorter than 0.5 s sits at a block edge. The last measurement block ends at the sound's end (48 kHz K-weighting). Read its loudness with that in mind.

Inputs and outputs

  • assets/sounds/<name>.json — layer recipe: duration, variations, pitch spread, global fx, and a list of layers each with a role, source, seed, filter, and envelope.
  • assets/sounds/sets/<set>.json — set definition: shared DNA (reverb, sub weight, brightness band), member sound names, weights, and one loudness level per class.
  • assets/sounds/_events.json — the game event map: event name to sound name, bus, blend key, and playback parameters.
  • assets/sounds/references.json — reference recordings you chose in the booth; these are the measurement targets for the match stage.
  • assets/sounds/ambience/<World>.json — ambience zone definitions: bed sounds, event densities, reverb zone, WindVoice, GustEvents, and EchoZones per region.
  • build/sounds/sheets/<name>.png — waveform, spectrogram, and ears measurements alongside the reference.
  • build/sounds/av/<name>.mp4 — the sound on its picture, from kit sfx av.
  • src/shared/<World>Ambience.json — ambience zone data synced to ReplicatedStorage.
  • build/sounds/ambience/<World>.png — visual map of the ambience zones.
  • Uploaded audio asset IDs in assets/ids.json.

All sounds are played through ReplicatedStorage.kit.Sfx. The runtime sits on top of the Roblox Audio API: AudioPlayer → AudioEmitter → AudioListener per bus → AudioFader per bus → master AudioCompressor → AudioDeviceOutput. Each bus has its own AudioInteractionGroup, so faders, ducking, and snapshots act independently per bus.

Playing sounds

-- Play a sound at a part (3D, spatialised on the sfx bus)
Sfx.play("SwordHit", { at = hitPart, surface = "metal", weight = 0.8 })

-- Play a sound with no position (2D — UI clicks, music, notifications)
Sfx.play("UiClick", { at = nil })

-- Play with a volume and pitch override
Sfx.play("FootstepStone", { at = character.HumanoidRootPart, volume = 0.9, pitch = 1.05 })

-- Broadcast from the server so every client hears it at the same position
-- `except` skips the client that already played it locally (client prediction)
Sfx.broadcast("SwordHit", hitPart.Position, { surface = "metal", weight = 0.8 }, attackerPlayer)

-- Preload a set of events ahead of an encounter
Sfx.preload({ "SwordHit", "SwordSwing", "SwordBlock" })

Buses, ducking, and snapshots

-- Blend all bus volumes to a named snapshot over 0.5 s (nil reverts)
Sfx.snapshot("combat", 0.5)

-- Set a player-controlled bus volume (e.g. from a settings slider)
Sfx.setBus("music", 0.4)

-- Query voice counts, dropped sounds, and per-bus usage
Sfx.stats()   -- { voices, byBus, dropped }

Reverb and the acoustic graph

-- Set the spatial reverb zone for the current area (nil = dry)
Sfx.reverb("HallStone")

-- Inspect the built audio graph (for playtests)
Sfx.graph()   -- { root, reverb, acoustic }

Ambient and environmental audio

kit.Ambience plays the zone's bed and event sounds from <World>Ambience.json. kit.WindVoice drives a tonal wind voice from cavity physics and the global wind value. kit.GustEvents fires rare audio moments on strong gusts. kit.EchoZones answers the player's own steps with a late reflection. All are data-driven; you configure them in the ambience JSON rather than writing Luau.

-- Derive ambience zones from a world blueprint
lune run parallax sfx ambience MyWorld

Commands

# Start the lane (required before any other sound command)
lune run parallax start sfx --prompt "weapon hits for a sword fighter"

# Direction
lune run parallax sfx direction SwordSounds --new    # generate three directions
lune run parallax sfx sketch scene.json              # build a sketch for the board
lune run parallax sfx board                          # play sketches; you pick one

# Reference search and selection
lune run parallax sfx find "heavy metal impact"             # keyword search
lune run parallax sfx find "dense thud with tail" --describe # CLAP semantic search (needs index)
lune run parallax vision setup clap-general                 # fetch the CLAP model once
lune run parallax sfx clap index                            # index library for CLAP search
lune run parallax sfx listen candidates                     # play candidates in the booth

# Identity
lune run parallax sfx identity MyGame --from <files>  # derive the sonic identity from references

# Build sounds and sets
lune run parallax new sound sword_hit_metal          # create a sound spec
lune run parallax sfx all                            # build all changed sounds
lune run parallax sfx set SwordHits                  # build a sound set

# Match and measure
lune run parallax sfx match sword_hit_metal --to ref_impact  # CMA-ES fit to reference
lune run parallax sfx sheet sword_hit_metal --ref ref_impact # waveform + spectrogram sheet

# Booth and verdict
lune run parallax sfx listen sword_hit_metal         # play in the booth
lune run parallax sfx listen sword_hit_metal --blind # play blind (identity hidden)
lune run parallax verdict sound sword_hit_metal 8 "heavy, clean tail"

# Sound on picture
lune run parallax sfx av sword_hit_metal --video capture.mp4 --at 1.42

# Catalog and runtime
lune run parallax sfx catalog                        # validate _events.json
lune run parallax sfx soundscript                    # lay sounds out in journey order

# Ambience
lune run parallax sfx ambience MyWorld               # derive zones from blueprint

# Upload
lune run parallax upload --only assets/sounds/SwordHits          # upload the set
lune run parallax upload --only assets/sounds/SwordHits --status # check moderation

How it learns

Verdicts of 7 or higher go into the golden set. Verdicts of 3 or lower go into the graveyard, the lane's record of failed routes, which every new session sees when it starts (a synth-only sword set graded down across rounds is the recorded example).

Record a technique or trap at any time:

lune run parallax lesson sfx "unseed short noise bursts — a 90ms thud swung 8% to 38% sub between takes"

After six or more verdicts, the taste profile (kit/knowledge/sfx_taste.json) learns what you reward. It appears as a report beside each take's measurements and at lane start — but it predicts only after your verdict, never before. It is a navigation aid, not a gate.

Tip

lune run parallax sfx find "<words>" searches the library before you build anything. Reuse a proven sound from the library rather than making a new one from scratch.

Known limits

Known limit

The pipeline cannot hear. Every decision at the match and sheet stages is made from numbers. The listening booth puts your ears in the loop — it is the only form of real-world quality assessment available.

Known limit

Synth-only sounds consistently score lower than layered-recording sounds. A synth-only sword set graded down across multiple booth rounds in practice. Use real recordings as the body layer where possible.

Known limit

BS.1770 loudness on a 0.5 s sound sits at a measurement block edge (the last block ends at the sound's end).

Known limit

A server started inside a Lune job dies with it, so the kit starts the booth outside the job (WMI breakaway, a per-launch token). Use kit sfx listen to start it and --stop to stop it.

Known limit

Private audio plays only where it has been granted. A Creator Store asset ID can be restricted per experience; always check moderation status after upload with --status.

A typical session

# 1. Start the lane with the request
lune run parallax start sfx --prompt "sword fighter: light hit, medium hit, heavy hit, swing, block"

# 2. Check the board for any work already in progress
lune run parallax status --dept sfx

# 3. Build a direction for the weapon set
lune run parallax sfx direction SwordSounds --new
lune run parallax sfx sketch sword_direction_a.json
lune run parallax sfx sketch sword_direction_b.json
lune run parallax sfx sketch sword_direction_c.json
lune run parallax sfx board     # play all three; pick one

# 4. Find and select reference recordings in the booth
lune run parallax sfx find "metal impact heavy"
lune run parallax sfx listen ref_candidate_1 ref_candidate_2 ref_candidate_3

# 5. Extract sonic identity
lune run parallax sfx identity SwordGame --from <reference files>

# 6. Build the set
lune run parallax new sound sword_hit_light
lune run parallax new sound sword_hit_medium
lune run parallax new sound sword_hit_heavy
# ... edit each .json with layers: transient, body, sub roles ...
lune run parallax sfx set SwordHits    # build all three; set gates run

# 7. Match to the reference
lune run parallax sfx match sword_hit_heavy --to ref_metal_heavy
# look at the sheet: open build/sounds/sheets/sword_hit_heavy.png
lune run parallax sfx sheet sword_hit_heavy --ref ref_metal_heavy

# 8. Listen in the booth and record your verdict
lune run parallax sfx listen sword_hit_light sword_hit_medium sword_hit_heavy
lune run parallax verdict sound sword_hit_heavy 8 "good sub on impact, tail is natural"

# 9. Watch the sound on a video capture
lune run parallax sfx av sword_hit_heavy --video playtest_capture.mp4 --at 2.14

# 10. Add events to the catalog and validate
# (edit assets/sounds/_events.json: map "SwordHitLight/Medium/Heavy" to the sounds)
lune run parallax sfx catalog

# 11. Upload and check moderation
lune run parallax upload --only assets/sounds/SwordHits
lune run parallax upload --only assets/sounds/SwordHits --status

# 12. Hand off
lune run parallax handoff "built SwordHits set: verdict 8 for heavy, catalog validated" \
  --lane sfx --next "build the swing cues" --as "kit"
