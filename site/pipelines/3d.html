Pipelines

3D Models

The 3D pipeline builds game-ready meshes — weapons, props, vehicles, creatures, building pieces — for Roblox in one planned pass. It starts from real references and sourced sizes, routes each part through the right tool (CAD for machined parts, generators for organic drafts), and ends with an optimised asset. Complex and hero pieces stop twice for your approval; props do not.

Tier 1+ 2 approvals (sheet, blockout) 10 / 30 / 60 min clock 10 stages

At a glance

Makes
Weapons, props, vehicles, creatures, and building pieces. Each asset is a Rojo model (.model.json) ready to spawn in Studio, plus a game-optimised low-poly mesh baked from the high.
Hardware
Tier 1 Blender 5.2 and the OpenCASCADE CAD environment are required for all builds.
Tier 2 Light vision models (cut-outs, depth, similarity) for reference work and coverage checks.
Tier 3 Local VLM (qwen3-vl-4b) for reference inventory and engraved-text reading.
Tier 4 3D draft generators (TRELLIS.2, Pixal3D, Hunyuan3D-2mv, PartCrafter) for organic-part drafts only.
Your approvals
Two hard stops for a complex or hero asset: the model sheet (every hero feature drawn with sourced sizes, before any build) and the blockout (big shapes in clay, before any detail or bake). Props skip both.
Clock
Prop: 10 min · Complex: 30 min · Hero: 60 min of build time per attempt. The clock starts at the first build. Past budget, nothing new is built until you reopen it with your words (kit plan <name> --extend <min> "<your words>", or --restart "<your words>" for a new attempt).
Results land in
build/renders/<name>.png (six views + feature close-ups), src/models/<name>.model.json (Rojo model), and, after lune run parallax upload, the asset ids in assets/ (uploads.json and the id files).

The flow in one line

brief→ gather + study→ sheet (you approve)→ draft (organic parts)→ blockout (you approve)→ shape→ surface→ mechanism→ judge→ ship

Props run this entire flow inside a single timed command (kit make <name> "<object>" --tier prop, ~6 min). Complex and hero assets stop at the two approval points and resume once you approve.

The stages

  1. 0
    Brief Define what it is, set its budget tier, list the hero features, and choose a build route per part.

    The brief file (<name>.brief.md) records: what the asset is, its tier (prop / complex / hero), which features must work correctly, whose design it follows, and a parts plan — a build route for each part family (machined, organic, cloth, thin plate, and so on). The tier is the budget and the quality bar; it cannot be raised by editing the brief after a build has started.

    lune run parallax new asset <snake> [--from sword]
  2. 1
    Gather Collect every reference before any shape is made, then lock the route with a study.

    This stage builds the asset's pack: a dossier of approved facts, sourced sizes, and pictures; two reference models graded for quality (noise, holes, missing detail); traced outlines for every view and part; and reference-model sections for hard-surface parts. Coverage must reach ≥ 2 px/mm per hero feature before you move on.

    The pack ends with the study: you read each reference, decide what your version keeps, changes, adds as a signature, and sets as target numbers. Each matched vault lesson is applied or skipped with a written reason. The study locks the shape; changing the route later means answering every lesson again from scratch. Copied answers are rejected.

    # dossier, reference models, traced views
lune run parallax refs find "<object>"
lune run parallax refs expand "<idea>"
lune run parallax refs dims find "<object> [part]"
lune run parallax refs patent <D-number>
lune run parallax refs coverage <name>
lune run parallax vision cutout <picture> --rgba
lune run parallax vision upscale <picture> --x 4

# lock the study (required before any build)
lune run parallax study <name> --new
  3. 2
    Sheet you approveDraw the model sheet — every hero feature pictured, sized, and at ≥ 2 px/mm — before any build.

    The model sheet is a single page that shows every view of the asset and, for each hero feature named in the brief, a cropped picture box, its sourced size, and confirmation that the box is at least 2 px/mm. It is refused while any hero feature is missing a box, a size, or falls below the coverage threshold.

    Props skip the model sheet. For complex and hero assets the sheet must be approved before any 3D generator or build command will run.

    Record your approval words exactly, because a changed sheet needs a new approval.

    lune run parallax sheet <name>
lune run parallax approve 3d <name> "<your words>" --by owner --stage sheet
  4. 3
    Draft Run a local 3D generator for each organic part only, with the GPU otherwise idle.

    Generators (TRELLIS.2, Pixal3D, Hunyuan3D-2mv, PartCrafter) are used as look targets for organic parts such as sculpted grips, creature bodies, ornament reliefs, and draped cloth. They are never used for a hero's hard-surface final mesh — a machined barrel, a slide, a housing. Each generated mesh must pass topology and side checks (glb_topology, side_check) before it enters the build.

    Organic ornament also follows a picture-first route: redraw the reference crop large with the local image model, generate from that one picture, then check the shape against every view before adding any detail.

    # draft generators (Tier 4 only)
lune run parallax gen views <name> --view side=<rgba.png> --view front=<rgba.png>
lune run parallax gen parts <name> --image <picture> --parts <1-16>
  5. 4
    Blockout you approveBuild the big shapes only, as clay, and approve proportions before any detail or bake.

    The blockout is a fast shape pass — no baking, no textures, no fine detail. It draws a blockout sheet from a shape round and shows proportions against the model sheet. You must approve the blockout before any detail work, baking, or surface pass will run.

    Like the sheet, the approval holds for what you saw. A redrawn blockout needs a new approval.

    lune run parallax blockout <name>
lune run parallax approve 3d <name> "<your words>" --by owner --stage blockout
  6. 5
    Shape Match every traced view to ≥ 0.9 and build each part by the method its plan names.

    Every traced view is matched against the model using a.trace_match. A view must hit ≥ 0.9 or be explicitly excluded with a written reason; a hero with no traced view at all fails as "unmeasured". For hero hard-surface parts, cross-sections must be within ≤ 1.5 mm of a reference model.

    Part-by-part routes are enforced: the kit rejects a build if a part is not made by the method its plan declared. The main families:

    • Machined / hard-surface: CAD from mm profiles (a.cad, rbx.profile), fillets and booleans in OpenCASCADE, sections checked against a reference model.
    • Organic ornament: a checked reference mesh as clay (a.form_match) or a per-part generator draft with relief.
    • Cloth: rbx_garment drape simulation.
    • Thin plates / rims: s.strap.
    • Designed / fictional object from orthographic renders: trace the side view into parts, take widths from the top view, sections from the front view.

    Proportions are auto-fitted with CMA-ES (kit fit). Every traced view is opened and checked after each shape round — scoring alone is not enough.

    lune run parallax asset <name> --geo
lune run parallax asset <name> --geo --only <part>
lune run parallax cad check <name> [--only <Part>,<Part>]
  7. 6
    Surface Apply a material per part from sourced data, engrave markings at measured positions, add wear from use.

    Every part gets a material with a data source (scanned texture, real-world values). Markings are engraved at positions measured from references. Wear follows the kind of use: a.contact("hand"|"rub"|"ground"|"drip") applies scratches, polish, rust streaks, or grime to the right surfaces. Dust lands on faces that point up.

    Tertiary detail — rivets, screws, panel lines, knurling, grille, ornament reliefs — is stamped into the normal map (no extra triangles). Drawn ornament (scrollwork, filigree, crest lines) is authored from its own SVG or PNG into the same normal-map route. A texel narrower than the map can represent is flagged by the stamp_texels warning.

    The game mesh (low-poly) is baked from the high-poly CAD solid. Each part bakes only from its own high, so no two parts trade normals. The texel density target is ≥ 1 texel per screen pixel at the asset's judging distance (1028 px/m for hero, 257 px/m for prop).

    lune run parallax asset <name>
  8. 7
    Mechanism Hero only: prove every joint moves without collision, then run the action cycle and disassembly.

    This stage applies only to hero assets with moving parts. Each joint is checked through its full travel: no moving part sits inside another at rest, no barrel passes through a wall, no trigger is inside its housing. The check runs at five stops and reports which parts intersect and roughly where.

    The action cycle (a.cycle) runs on the Blender timeline with every joint posed together. The disassembly (a.disassembly) separates every part cleanly.

    lune run parallax asset <name>
  9. 8
    Judge The verifier compares a reference crop to the render crop per view; one edit per round, up to 10 rounds, then your verdict.

    The judge step renders the same camera crop from the reference photo and from the model, side by side, for every traced view. The session proposes one edit per round. After at most 10 rounds you give your verdict (kit verdict asset <name> <0-10> "...").

    Always open the renders yourself before giving a verdict — the pipeline's scores and green gates are not a substitute for looking at the actual images.

    lune run parallax judge <name>
lune run parallax verdict asset <name> <0-10> "<your words>"
  10. 9
    Ship Build the game version, spawn it in Studio, and upload. Promote only on a verdict ≥ 7.

    kit optimize builds the game-ready low-poly mesh (prop budget: ≤ 5,500 triangles). It must spawn in Studio. Public assets are uploaded with kit upload: the Studio MCP sends each file (open_cloud_invoke with your Studio login), so no API key is required; with ROBLOX_API_KEY set, the kit uploads by itself. The ids are recorded in assets/.

    kit promote asset <name> --about "..." adds the asset to the kit's example library, but only on your verdict of 7 or above and a gate that passed after its last edit. kit sync pulls the kit's lessons and examples into a project.

    lune run parallax optimize <name>
lune run parallax upload
lune run parallax verdict asset <name> <0-10> "<your words>"

Inputs and outputs

  • assets/models/<name>.brief.md — tier, hero features, parts plan, similar/from fields.
  • Dossier JSON — approved facts, source words, graded pictures and reference models.
  • Patent figures, turntable references, two reference .glb models.
  • Traced views (outline curves per view and per part).
  • refs/<name>.spec.json — every part named, described, and attached.
  • Direction JSON (for original / fictional designs).
  • assets/plans/<name>.plan.json — tool plan per part for heavy builds.
  • build/renders/<name>.png — six views at ≥ 1,024 px each.
  • build/renders/<name>_lines_<view>.png — reference / model / diff overlays.
  • build/renders/parts/<name>_parts_*.png — per-part tiles in context and isolated.
  • build/judge/<name>/ — full judge packets with reference and render crops.
  • src/models/<name>.model.json — Rojo model for Studio.
  • Uploaded Roblox asset ids in assets/ (uploads.json and the id files).
  • <name>_high.blend — full-detail Blender source beside the build.

kit optimize produces the game mesh (low-poly, baked normals, colour, roughness, metalness). It spawns in Studio via kit showcase. Upload it with kit upload: the Studio MCP's open_cloud_invoke sends each file, so no ROBLOX_API_KEY is required. The ids are stored in assets/, and src/models/<name>.model.json is rewritten so Models.spawn("<name>") builds the real model.

How it learns

Verdicts and the golden set

Every verdict feeds the kit's memory. A verdict of 7 or above adds the asset to the golden set — the reference calibration for future quality checks. A verdict of 3 or below puts its build route in the graveyard; that route is refused on the next similar piece without your explicit words to override it.

After five new verdicts, kit start asks for kit vault distil 3d first: it turns the new evidence into written rules for the lane.

The study step

The study is not a one-time task. It runs before every new piece and answers: what does each reference do well, what do all the good ones share, and what does your version keep, change, and add as a signature? The best-matching vault lessons (up to five) must each be applied or skipped, with at least six words on how or why.

If you change the build route — moving from CAD to a generator, for example, or adding a simulation step — you must run kit study <name> --reroute and answer every lesson again. Copied answers are rejected; the kit tracks what was written for which route.

Lessons

Lessons are ranked by relevance for each asset at session start. They must be answered before the quality locks pass. A lesson added after a verdict is live on the next build. Run lune run parallax lessons 3d for the full list.

Promoting work

kit promote asset <name> --about "..." adds proven work to the kit's example library so future pieces can start from it (kit new asset <x> --from <name>). kit sync pulls the kit's lessons and examples into a project.

Known limits

Known limit

OpenCASCADE refuses fillets over traced perimeters: round only the edges that read, or redraw the outline tangent. Coplanar faces are the most common boolean failure; overshoot cutting bodies and inset mating outlines ~0.15 mm.

Known limit

Whole-object generator meshes are never accepted for a hero's hard-surface final mesh. Generators (Tier 4) are look targets for organic parts only. Hero hard-surface parts must be built part by part from CAD or traced reference outlines.

Known limit

Generated turned views are unreliable for thickness. Thicknesses for round parts must come from the director's section plan or from cross-sections measured against a reference model.

Known limit

The cad_solid gate can report open edges while kit cad check says 0 (an untrue volume). When that happens, bisect by mesh volume error to find the part, rather than guessing at the shape.

Known limit

Dense CAD tessellation folds a mesh bevel past about 0.3 mm; shaded rounds stay readable only at ≤ 0.8 mm. Wider reads as melted geometry.

A typical session

# 1. Start the lane with your request
lune run parallax start 3d --prompt "a ruined prop lantern"

# 2. Create the asset and read the brief template
lune run parallax new asset ruined_lantern
# edit assets/models/ruined_lantern.brief.md: tier, hero features, parts plan

# 3. Gather references (dossier, two reference models, traced views)
lune run parallax refs expand "a ruined iron lantern"
lune run parallax refs find "iron lantern"
lune run parallax vision cutout <picture> --rgba   # cut out from background
lune run parallax vision upscale <picture> --x 4  # 4x a small reference crop

# 4. Lock the study (required before any build)
lune run parallax study ruined_lantern --new

# 5. This is a prop — run the whole pipeline in budget
lune run parallax make ruined_lantern "a ruined iron lantern" --tier prop

# 6. Open the renders beside the references and check
# build/renders/ruined_lantern.png

# 7. Give your verdict
lune run parallax verdict asset ruined_lantern 8 "shape is right, good patina"

# 8. Ship to the game
lune run parallax optimize ruined_lantern
lune run parallax upload
lune run parallax promote asset ruined_lantern --about "a ruined iron lantern"

For a hero asset, insert the sheet and blockout approval steps between gather and shape, and expect multiple shape rounds before the judge step. The clock limits each attempt to 60 minutes of build time.
