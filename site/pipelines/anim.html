Pipeline

Animation

Build R6 character animations that are measured, not guessed. Every clip starts with a move dossier of the real move, is authored from scratch by a procedural spring engine calibrated against Roblox's native R6 catalog, passes motion gates, and is proven in Studio frame by frame before upload.

Tier 1+ for Blender 2–3 approvals 10 / 30 / 60 min clock

At a glance

Makes
R6 KeyframeSequence animations: attacks, abilities, emotes, idles, hit reactions, locomotion cycles, cutscenes, and prop clips. Each clip ships as a Rojo model and an uploaded Roblox asset ID.
Hardware
Tier 0 Motion building and gates require only a CPU. Tier 1+ Blender 5.2 is required for rig-based authoring, retargeting imported clips, and the Blender authoring route.
Your approvals
Up to three: (1) the design page for an attack string, before any single move in the string is built; (2) the key-pose blocking sheet for each individual strike, sword, or kick move; (3) your verdict on the finished clip, 0–10.
Clock
10 min for a simple clip, 30 min for a complex one, 60 min for a hero clip (requires explicit approval to reach that tier). The clock starts when you run lune run parallax anim <Name> or lune run parallax anim bake <Name>. Past the budget, no change rebuilds the clip; show what exists and wait for your words to reopen it.
Results land in
build/animations/<Name>.clip.json, build/animations/<Name>.sheet/ (pose sheet, timing chart, gif), src/animations/<Name>.model.json (Rojo model). The runtime reads clips from ReplicatedStorage.KitAnimations.

The flow in one line

dossier → design page (you approve, strings only) → key-pose blocking (you approve) → candidates → motion gates → pick gallery → Studio proof → verdict (you score 0–10)

Approval steps are marked. The design page applies only to an attack string; the blocking applies to strike, sword and kick moves. Promotion needs your verdict of 7 or above.

The stages

  1. 1
    DossierMeasure the real move from footage; write the move dossier.

    Every clip starts with a move dossier (assets/animations/dossiers/<move>.json): phase timings measured from real footage, the mechanics of each phase, what cues make it read clearly, common mistakes, and the R6 translation (how the move works on a rig with no knees or elbows: which joints slide, what the torso does).

    Footage is analysed offline with MediaPipe Pose. Files go in _artifacts/footage/<move>/ and are never committed. The dossier must carry measured evidence for every moving phase: a source with real timings (real_s) and where they were measured. A dossier built on inference alone, or one that lacks numeric checks, is refused at build time.

    Every rejection you give must be recorded in the dossier (owner_rejections) before a rebuild is allowed. A "bad" verdict blocks the rebuild until the dossier answers the rejection with what changed. This enforces the loop: record the verdict → re-research → update the dossier → build to the checks → look at the render → then show the result.

    lune run parallax new anim <PascalName>
# edit assets/animations/dossiers/<Name>.json
lune run parallax anim dossier check <Name>

    Produces: a schema-2 dossier with measured phase timings, numeric checks, an R6 translation, and a list of common mistakes.

  2. 1a
    Design page you approveDesign a string of attacks as one page before any individual move is posed.

    A set of related attacks is designed as one page before anything is posed. The design page specifies, for each attack: the cut direction (down, left, up, thrust, etc.), the height (high/mid/low), what the body does (plant, step in, lunge, spin, etc.), the intent (calm/proper/aggressive), frame budgets at 60 fps (windup, active, recovery), which pose the move ends in, and what may come next. The page also specifies how the game links moves in the string: by pose (each move ends where the next starts) or by blend (the game cross-fades).

    The check catches two attacks that are cousins: the same cut, height, and body action. It also measures whether the blade paths of two attacks are fewer than 2.8 studs apart on average; that too is a cousin pair, named with the attack numbers.

    You must approve the drawn page before any move in the string can be blocked or built. A new move is refused if its string has no approved design page.

    lune run parallax anim design <Set> --new --attacks 4
# draw and inspect the page:
lune run parallax anim design <Set>
# approve after viewing the page:
lune run parallax anim design <Set> --approve "<your words>" --by owner --id <id>

    Produces: assets/animations/designs/<Set>.design.json and build/animations/<Set>.design.png (a row per attack: the cut wheel, frame budget, three silhouettes, the string's rhythm bar, all problems listed).

  3. 1b
    Key-pose blocking you approveHold each key pose large, side by side with its reference frame; get your approval before motion is built.

    Before any motion is generated for a strike, sword, or kick move, the key poses are shown to you held still, large, from three views (player camera, side, top), beside the dossier's reference frame for that phase. A real-time GIF shows the poses playing at the right hold durations.

    You can note what is wrong on any pose (--note <pose> "words"). The note travels with the pose through edits. The next sheet print marks each note as answered (what changed in that pose's own key) or not answered (unchanged, or changed only by its neighbours).

    Your approval is a yes to the poses as they are now. Any later change (a pose turned, retimed, added, or dropped) makes the approval stale and holds the build again. The finished clip is also held to the approved poses: each pose is looked for in the clip at its own moment (within 0.05 s, with a tolerance of 10°/0.25 studs for joints and 1.25 studs for the blade tip). A pose the clip never reaches fails with the joint name and the amount it is off.

    lune run parallax anim block <Move> --sheet
# inspect every keys/ page at full size, then show the sheet and gif
lune run parallax anim block <Move> --note 3 "left arm is wrong"
lune run parallax anim block <Move> --approve "<your words>" --by owner --id <id>

    Produces: build/animations/<Move>.blocking/ containing blocking.clip.json, the pose sheet PNG, the GIF, and reference columns.

  4. 2
    AuthorGenerate candidates from scratch on the procedural spring engine, calibrated against the native R6 catalog.

    The kit builds candidates from scratch using its procedural spring engine. The route depends on the clip type:

    • Strike moves: a director beat script drives gesture specs, which drive a pose prior, which drives the proc_r6 spring engine at dense 60 fps. Calibrated bands from the native R6 catalog control snap timing (~0.2 s then hold), joint slides (0.6–1.7 studs), torso speed at the hit (1,100–3,300 deg/s), and head/arm drag (3 and 2 frames respectively). Candidates differ by effort sliders, arm habits, and blade lines.
    • Weapon moves: a weapon dossier drives proc_blade. Grip, direction, torso yaw/pitch/roll, foot placement, overshoot, and lag are authored directly. The free arm takes a loved arm habit or a pose-prior mode plus whip.
    • Locomotion: normative gait curves (from published biomechanics data) drive the generator. Approved R6 catalog runs carry the legs forward by sliding them and pump the forward hand across the midline.
    • Library clips: vetted CC0 or CC BY clips can be imported (kit anim import), but they are the bar and the calibration, never the source of a finished move: motion folded to R6 from other engines is in the graveyard.
    • Blender authoring: you author on the kit rig in Blender using IK and NLA, then bake back to the kit's clip spec.

    The intent (calm / proper / aggressive) is a first-class input. It is read from the R6 strikes' own tempo thirds: each intent samples its own effort range, and a candidate that reads as a different intent is refused.

    About 2.5× the final gallery count of gate-clean candidates are built. Eight that are most different from each other (by motion distance, not by slider distance) are chosen for the pick sheet. With prior picks and rejections from earlier rounds of the same generator, half of the pool is likely-good candidates and half are informative ones that explore the edges.

    lune run parallax anim candidates <Name> --dossier <move> --n 8
lune run parallax anim candidates <Name> --intent calm
# breed from picks:
lune run parallax anim candidates <Name> --round 2 --parents a,b

    Produces: build/candidates/<Name>/round_K/ with clip JSON files, GIFs, pose sheets, and metrics.

  5. 3
    Motion gatesAutomated checks that block any candidate that fails physics and readability rules.

    Every candidate passes a set of motion gates before it is shown to you. These are filters, not rankings: a candidate that fails any gate is dropped from the pool entirely.

    The gates are described in the Gates section below. Beyond the numeric thresholds, the kit also runs:

    • Weapon-in-hand check: at every frame, the nearer hand must be within 0.1 studs of the weapon's hilt-to-tip line. A clip whose weapon is in no hand fails with the frame range.
    • Penetration check: the weapon, hands, and feet are swept against the body's collision boxes between frames. Any contact that is not declared in the move fails with the part and frame.
    • Procedural gates: readable, statue, face, floaty, robot_arm, jitter, copy_floor, style_band and frozen_limb filter candidates too.
    • Human-vs-machine critic (a command you run): lune run parallax anim critic <clip.json> scores a clip with a classifier trained on loved R6 clips versus the moves you rejected. Below a P(human-made) of 0.5 it warns that the clip reads machine-made: rebuild it from real pieces rather than hand-posing frames. It does not filter candidates.
    • R6 vocabulary gate: the kit measures per-phase joint slides, arm habits, and whip against the range the loved native R6 clips show. A limb frozen below the loved minimum on both slide and turn fails. Measures below the loved 10th percentile are manifest warnings.
    • Dossier checks: numeric checks authored in the dossier (e.g. a maximum knee travel, a minimum hip turn) are run on every candidate. A strike clip that misses one of its own dossier checks is not built; checks that an arm choice is not held to are warnings.
    # gates run automatically inside kit anim candidates
# run the critic alone:
lune run parallax anim critic build/candidates/<Name>/round_1/<id>.clip.json
  6. 4
    Pick galleryView candidates as real-time GIFs from the player's camera; pick one to build into a game clip.

    Gate-clean candidates are shown as a gallery: real-time GIFs from the player's camera (every 4th frame at 66 ms; every 2nd frame for fast cuts or spins at two or more turns per second). Each card shows the kit's warnings (a limb or blade below the loved range) underneath the GIF.

    You pick one or more candidates. Your picks and rejections steer the next round: half the new candidates are likely-good (near the picks), half are informative (away from the rejected region). An "all bad" response steers the next round away from everything that was rejected. Gallery tuning tracks what the pool has learned from your choices.

    Once you have picked a candidate, it becomes the basis for the game clip. The game clip spec references the candidate by its round number and ID, so the kit can reproduce the exact motion from tracked parameters.

    lune run parallax anim candidates <Name>
lune run parallax anim picks <Name> --round 1
lune run parallax anim gallery <Name>

    Produces: a standalone HTML gallery page with every GIF embedded. kit anim gallery <Name> shows what the gallery has learned from your picks.

  7. 5
    Studio proofStep through the clip frame by frame on a fresh R6 humanoid in Studio; compare every joint against the clip.

    The candidate you picked becomes a game clip. The kit rebuilds it from the tracked candidate parameters and bakes the full 60 fps clip. Then it proves the clip in Roblox Studio, frame by frame, on a fresh humanoid (never the client-owned player).

    The proof compares every joint against the clip at a tolerance of 2° and 0.05 studs. Markers in the clip (Hit, ActiveStart, etc.) are checked within ±1 frame of their authored time. A joint that is off by more than the tolerance fails with the joint name and the amount.

    The look command (lune run parallax anim look <Name> --rig R6) renders the clip in Blender on the kit rig, as a person judges it. The play command (lune run parallax anim play <Name> --rig R6 --run --studio <id>) is the frame-by-frame proof that must pass: the kit runs the probe in the Studio window you name, which you open on a copy of build/place.rbxlx; never a shared Studio.

    lune run parallax anim <Name>              # build the game clip
lune run parallax anim look <Name> --rig R6
lune run parallax anim play <Name> --rig R6 --run --studio <id>   # frame-by-frame proof

    Produces: src/animations/<Name>.model.json (Rojo model), build/animations/<Name>.metrics.json, and Studio proof results in the terminal.

  8. 6
    Verdict and ship you score 0–10Record a verdict, upload, and promote if the score is 7 or above.

    After the Studio proof, you give a verdict: a score from 0 to 10 and your words. A score of 7 or above adds the clip to the golden set, which calibrates the quality bar for future clips. A score of 3 or below puts the route in the graveyard, which the pipeline refuses to repeat without your explicit permission.

    Every rejection must be answered in the dossier before a rebuild is allowed. A rejection without an updated dossier blocks the next build.

    lune run parallax verdict anim <Name> 8 "loved the shoulder read"
lune run parallax anim judge <Name>    # judge packet for reviewer
# upload after a good verdict:
lune run parallax upload

    Promotes to ReplicatedStorage.KitAnimations. The runtime plays the clip via local Anim = require(ReplicatedStorage.kit.Anim); Anim.play(humanoid, "Slash"). Hit markers connect via track:GetMarkerReachedSignal("Hit").

All gates run inside lune run parallax anim <Name> and inside kit verify on every built clip. Thresholds can be overridden per spec under "gate".

Note

Roblox samples curve animations at 30 frames per second. A clip authored at 60 fps loses its odd frames when exported as a CurveAnimation, up to 5.2° on a fast cut's arm. The kit keeps its own clips as KeyframeSequences (every frame plays). A clip made at 30 fps may be exported as a CurveAnimation at no loss.

Inputs and outputs

  • assets/animations/dossiers/<Name>.json: move dossier (phase timings, mechanics, R6 translation, numeric checks, reference frames from real footage).
  • assets/animations/designs/<Set>.design.json: approved attack string design page.
  • assets/animations/blocks/<Name>.blocking.json: approved key-pose blocking record.
  • assets/animations/<Name>.move.json: weapon move spec (grip, direction, torso, foot schedule, overshoot, lag).
  • assets/animations/<Name>.pose.json: hand-posed keyframe spec for R6 attacks.
  • assets/animations/<Name>.json: keyframe spec for other clips (character-space keys, beats, events, feel).
  • assets/animations/<Name>.blend: Blender source file, once authored on the kit rig.
  • assets/rigs/R6_IK.md: kit rig documentation (drive controllers, never copy the armature).
  • _artifacts/footage/<move>/: private footage files, never committed. The footage is used offline for MediaPipe Pose analysis.
  • build/animations/<Name>.clip.json: the full 60 fps clip data.
  • build/animations/<Name>.sheet/: pose sheet (pose_sheet.png), keys/ (each pose large, full-size), strip_player.png / strip_side.png, timing.png (timing chart).
  • build/animations/<Name>.metrics.json: gate results, R6 vocabulary measures, timing chart readings.
  • build/animations/<Name>.r6.blend: Blender file for scrubbing the R6 result.
  • build/candidates/<Name>/round_K/: candidate clips, GIFs, and metrics.
  • src/animations/<Name>.model.json: Rojo model for Studio.

The runtime also supports pose matching (enter a clip at the frame nearest your character's current pose), distance matching (enter at the frame that far from the stop), secondary motion (accessory sway on a spring), ragdoll get-up blends, motion warping (root travel cut short of walls), and cutscenes synced across all clients on the server clock.

How it learns

The pipeline improves from every clip you score.

  • Golden set: clips with a verdict of 7 or above join the golden set. The golden set calibrates the procedural spring engine: speed, amplitude, lag, slides, and gate thresholds are measured from these clips. Future candidates are held to the same standards.
  • Graveyard: a clip with a verdict of 3 or below puts its route in the graveyard. The route is refused for future clips of the same kind until you explicitly permit it. The faults you name are measured on the real clips you rejected (kit/anim/owner_faults.py) and gate every generated weapon candidate; kit selftest proves each one.
  • Human-vs-machine critic: the critic is trained on loved native R6 clips and the moves you rejected; re-train it (python kit/anim/motion_critic.py train) as both sets grow. A clip that passes the numeric gates but reads as machine-made is rebuilt from pieces.
  • Gallery tuning: your picks and rejections on the candidate gallery steer the axes of the next round. The gallery tracks what the generator has learned from your choices for each move. After an "all bad" response, the next round steers away from every rejected region.
  • Dossier loop: every rejection must be answered in the dossier before a rebuild. The dossier records what was learned, what changed, and what the new checks are. This prevents rebuilding blind.
  • Vault distillation: after enough new verdicts, the kit can distil evidence into live rules for the vault.

Known limits

Known limit

No locomotion start, stop, or pivot clips exist yet. The runtime API (start, stop, pivot, turnLeft, turnRight) is built and ready, but the library has no such clips to fill it.

Known limit

Prop clips are built and gated against the prop's joints, and the runtime has a prop player (AnimProp: an AnimationController and Animator on the spawned model, stepped on the character's clock), but the kit's skill does not yet record a prop clip proven in Studio. The check that clips still fit a rebuilt model (--check) does not run by itself.

Known limit

Roblox samples curve animations at 30 frames per second. A 60 fps clip loses its odd frames, up to 5.2° on a fast arm cut. The kit's own clips stay as KeyframeSequences and are not affected.

Known limit

The R6 motion model is not suitable for combat moves yet; the procedural spring engine outperformed it on loved attack clips. The model is used only for filling long gaps in imported locomotion clips.

Known limit

Runtime rules (foot placement, motion matching, pose matching, get-up blends, secondary motion) have been written and pass their spec tests, but several of them (reading the pose and ground off a live character, writing the answers after the Animator, capturing a ragdoll's pose) have not been seen to move in a live Studio session.

A typical session

# 1. Start the lane with your request
lune run parallax start anim --prompt "a two-handed katana combo, three attacks"

# 2. Check the board for the current task
lune run parallax status --dept anim

# 3. Claim the task
lune run parallax task claim <id> --as "building the kesa combo"

# 4. Build the move dossier for the first attack
#    - measure footage offline with MediaPipe Pose
#    - write phase timings, R6 translation, numeric checks
lune run parallax anim dossier check KesaKiri

# 5. Design the full three-attack string
lune run parallax anim design KatanaCombo --new --attacks 3 --weapon sword
lune run parallax anim design KatanaCombo
# → inspect build/animations/KatanaCombo.design.png
lune run parallax anim design KatanaCombo --approve "looks right" --by owner --id <id>

# 6. Block each move's key poses
lune run parallax anim block KesaKiri --sheet
# → inspect build/animations/KesaKiri.blocking/ (every keys/ page at full size)
lune run parallax anim block KesaKiri --approve "good" --by owner --id <id>

# 7. Build candidates
lune run parallax anim candidates KesaKiri --dossier katana_swing --n 8 --intent calm

# 8. Pick from the gallery
lune run parallax anim picks KesaKiri --round 1
# → pick candidates a and c

# 9. Breed a second round from the picks
lune run parallax anim candidates KesaKiri --round 2 --parents a,c --n 8

# 10. Build the game clip from the chosen candidate
lune run parallax anim KesaKiri
# → inspect build/animations/KesaKiri.sheet/ (every keys/ page, timing.png)

# 11. Studio proof
lune run parallax anim look KesaKiri --rig R6
lune run parallax anim play KesaKiri --rig R6 --run --studio <id>

# 12. Record a verdict
lune run parallax verdict anim KesaKiri 8 "smooth shoulder lead, right timing"

# 13. Upload and hand off
lune run parallax upload
lune run parallax task done <id>
lune run parallax handoff "built KesaKiri (8/10), two attacks remaining" --lane anim \
  --next "block MakkoOroshi next" --as "agent"
